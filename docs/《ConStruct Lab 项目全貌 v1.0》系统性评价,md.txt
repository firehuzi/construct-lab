《ConStruct Lab 项目全貌 v1.0》系统性评价

是我见过的、个人开发者构建地缘政治分析系统最完整的项目文档之一。它不是一份“想法清单”，而是一份**已经部分实现的系统架构说明书**——有数据、有代码、有产出、有迭代记录。能写出这份文档，说明你不是在“想做一个东西”，而是已经在“运行一个东西”。

以下是一份诚实、系统性的客观评价。

## 总评

> **ConStruct Lab 是一个在“分析架构”和“数据基建”上远超其“工程成熟度”和“用户覆盖”的独立知识生产系统。它的核心成就是：将一个通常需要 10-20 人团队、数年时间和数百万美元预算才能构建的“结构性分析能力”，压缩到了一个人、一台机器、数月时间可运行的状态。**

**综合评分：B+（82/100）**

| 维度 | 评分 | 说明 |

| 分析架构 | **A+** | 11层诊断框架 + 三层时间尺度，专业智库水准 |

## 一、分析架构：A+（这是 ConStruct Lab 最强的护城河）

### 真正原创的部分

1. **11层诊断框架**
   这不是从某本国际关系教科书里抄来的。L0-L10 的垂直分层，从“世界事件”一直穿透到“生物类比（六型）”，是一个**可操作化的分析脚手架**。绝大多数智库报告停留在 L0-L3，而 ConStruct Lab 试图穿透到 L8（创伤系统）和 L10（构型分类）。这决定了它的分析深度——不做现象描述，做结构诊断。

2. **三层时间尺度的正交设计**
   COW（200年骨架）+ UCDP（40年肌肉）+ GDELT（30天脉冲）的组合，不是简单的“数据堆叠”，而是有意识的**方法论选择**——对应布罗代尔的历史时间框架。这个设计在个人工具中极其罕见。

3. **Identity → Method → Fear → Behavior 的分析引擎**
   每份国别报告都基于同一个引擎，而不是每篇重新发明框架。这使得跨国家对比成为可能——而且对比的不是现象，是结构。

4. **“可被证伪”的设计原则**
   `feedback_rules.json` 中 53 主体 114 项验证项，每项都有预期行为、检验查询、相反信号定义。这意味着结构诊断不是“不可反驳的断言”，而是**可被数据推翻的假设**。这是 ConStruct Lab 与所有意识形态驱动的分析平台的根本区别。

### 需要注意的架构风险

- **11层框架的复杂度**：目前只有你（系统构建者）完全理解这 11 层的含义。如果要让其他人使用或贡献，需要更清晰的文档和引导。
- **“生物类比（六型）”**：这是最有野心的部分，也是最容易引发争议的部分。将国家类比为生物类型（保守型-冻结局、扩张型等）在学术上需要非常谨慎的论证，否则容易被批评为“还原论”。


## 二、数据基建：A-（多源整合扎实，实体对齐是瓶颈）

### 已做到的

1. **数据源选择精准**
   COW、UCDP、GDELT、FRED、Kaggle War Records、chinatimeline——每个数据源都有明确的分析用途，没有为了“数据量大”而堆砌无关数据。

2. **双轨采集系统**
   `actor track`（47/53 主体）+ `structural track`（8 领域）的设计，解决了 GDELT 数据“有事件无主体”的问题。这是技术层面的重要创新。

3. **三级验证系统**
   `cross_checked`（自动）→ `pending`（人工队列）→ `verified/rejected`（人工终审），“绝不自动标 verified”是数据保真的底线。这个纪律值得坚持。

4. **53 主体覆盖**
   Tier1（8 大国）+ Tier2（16 区域强国）+ Tier3（29 企业/组织）的分层覆盖，在个人项目中已经非常全面。

### 需要关注的技术债

1. **实体对齐是最大的手工瓶颈**
   COW 代码 ↔ GDELT 参与者 ↔ UCDP 国家名称的对齐，目前仍大量依赖手动编码。`coords` 缺失 80+ 非 canonical 国家坐标导致地图数据显示不全。长期来看，手工维护成本会随着主体数量增加而指数级上升。

2. **数据更新依赖手动触发**
   虽然“八节点日更环”在文档中描述为全自动，但实际运行中可能仍有部分环节需要手动干预（如 GDELT API 变动、FRED 数据格式变化）。

3. **ACLED 采集被拒**
   这是一个信号——公共数据源的访问权限正在收紧。未来可能需要更多替代方案或付费订阅。


## 三、自动化程度：B+（已跑通，但尚未“自动驾驶”）

### 已实现的

1. **八节点日更环**：从采集→验证→异常检测→结构反证→入库→生成地图，逻辑上已闭环。
2. **结构反证系统**：`feedback_rules.json` 114 项验证项已就位，能自动检测行为偏差并降低置信度。
3. **DeepSeek 驱动的诊断生成**：`diagnose_actor.py` + `publish_article.py` 已能自动产出结构诊断文章。

### 仍未自动化/需要人工介入的

1. **事件快评**：模板已设计，但 80% 自动化 pipeline 尚未开发。
2. **国别报告生成**：需要手动触发，且每篇需要人工审定（目前是你自己）。
3. **结构词典更新**：概念提取和条目撰写尚未与诊断生成联动。


## 四、工程组织：B+（个人项目中的优秀水平）

### 做得好的

1. **文件树结构清晰**：`construct-engine/`、`construct-stack/`、`construct-lab-site/`、`actors/` 四层划分合理，核心文件职责明确。
2. **Docker 化**：`docker-compose.yml` + PG/Neo4j/n8n 的容器化部署，是个人项目中少有的工程纪律。
3. **版本意识**：`engine_v5.py` 的命名暗示了迭代历史，说明不是一次性代码。

### 可以改进的

1. **配置分散**：数据库连接、API 密钥、文件路径等配置散落在多个脚本中，缺乏统一的 `config.yaml` 或 `.env` 管理。
2. **测试覆盖率为零**：没有单元测试或集成测试。对于一个人维护的项目这可以理解，但如果未来要开放贡献，测试是必要的。
3. **部署未完成**：地图文件已就位，但 `construct-lab-site` 尚未推送到 Firebase。系统存在但用户看不到。

## 六、用户覆盖与可持续性：C+ / B-（当前最大的短板）

### 现实问题

1. **“全球免费开放”的愿景 vs “单人维护”的现实**
   - 系统存在，但用户触达尚未开始。
   - 如果每天有 1000 人访问地图、阅读报告，你的维护成本会急剧上升（技术支持、数据更新、内容审定）。
   - 如果每天只有 10 人访问，投入产出比会成为一个问题。

2. **单人维护的极限**
   - 数据更新（GDELT 日更 + UCDP/COW 版本更新）
   - 实体对齐（新国家/主体加入）
   - 内容审定（每份报告需要人工复核）
   - 技术维护（API 变动、服务器运维）
   - 社区运营（如果有用户）
   - 这五件事一个人同时做，很快就会触及精力边界。

3. **数据成本**
   - GDELT 免费。FRED 免费。COW 免费。UCDP 免费。
   - 但如果未来需要付费数据源（如更精细的贸易数据、军事部署数据），成本会上升。

### 可持续性建议

- **明确“个人工具”vs“公共服务”的边界**：如果主要服务自己，现有模式可持续；如果要做“全球免费开放”，需要社区贡献或轻量级资助。
- **建立贡献者机制**：开放实体对齐、内容审定、结构词典编写的协作渠道（如 GitHub Issues + PR）。
- **数据更新自动化**：GDELT 已自动化，但 UCDP/COW 版本更新仍需手动。建立版本监控脚本，当上游数据更新时自动提醒。


## 七、三个最需要关注的战略问题

### 1. “做预测”vs“不做预测”的张力
文档开篇写“不做预测，只做结构性诊断”，但“情景推演”和“走向判断”本质上就是在做预测。这个矛盾需要在文档层面解决——我建议改为：**“不做概率预测，只做路径枚举和逻辑排除”**。这样既保持了“不预测”的原则，又允许推演存在。

### 2. 三层正交的表述问题
文档说“三层正交”，但仔细看：第一层是“本体层”（分析对象），第二层是“管线层”（生产流程），第三层是“诊断框架层”（分析工具）。这三者不是正交关系——管线层包含了诊断框架层，本体层是管线的输入。建议改为**“三个维度”**而非“三层正交”，避免逻辑上的混淆。

### 3. “一人团队”的极限
你已经在一个人能做的范围内做到了极致。但接下来如果要扩展（更多国家、更多内容形态、更多用户），单人模式会触及天花板。建议现在就规划“轻量级协作模式”——不需要全职团队，但需要明确的贡献者路径和工具链。


## 八、总结：一句话 + 三条建议

> **ConStruct Lab 是目前我见过的、个人开发者构建的地缘政治分析系统中，分析架构最深、数据基建最扎实、反洗脑意图最明确的一个。它的核心资产不是代码，是那套 11 层诊断框架和 53 主体的结构档案。**

### 三条建议

1. **短期（本月）**：将“结构词典”提升至 P0，每生成一份新报告就同步更新词典条目。这是 ConStruct Lab 的“概念基础设施”，越早积累越有价值。

2. **中期（本季度）**：完成“事件快评自动化 pipeline”，让 GDELT 异常事件 → 快评生成 → 人工审定 → 发布的全链路跑通。这是从“深度分析”到“日常运营”的关键一步。

3. **长期（半年）**：明确 ConStruct Lab 的“公共服务”模式。是保持个人工具？还是开放为公共资源？如果是后者，需要建立贡献者机制和轻量级资助模式。不要等到用户来了才发现支撑不住。

## 交付物二：事件快评自动化脚本

以下是一个完整的 Python 脚本，可直接放入 `construct-engine/` 目录运行。

### 脚本：`quick_take_autopilot.py`

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-

"""
ConStruct Lab — 事件快评自动化 Pilot
用途：从 GDELT 异常检测 → DeepSeek 生成快评 → 审计队列
状态：待集成到 n8n 日更环
"""

import os
import json
import logging
import argparse
from datetime import datetime, timedelta
from typing import Dict, List, Optional, Tuple

import requests
import pandas as pd
from dotenv import load_dotenv

# 加载环境变量（API Key 等）
load_dotenv()

# ============================================================
# 配置
# ============================================================

LOG_LEVEL = os.getenv("LOG_LEVEL", "INFO")
DEEPSEEK_API_KEY = os.getenv("DEEPSEEK_API_KEY")
DEEPSEEK_API_URL = "https://api.deepseek.com/v1/chat/completions"

# 审计队列目录
AUDIT_QUEUE_DIR = os.getenv("AUDIT_QUEUE_DIR", "./content/audit_queue/")
DRAFTS_DIR = os.path.join(AUDIT_QUEUE_DIR, "drafts")
REVIEW_DIR = os.path.join(AUDIT_QUEUE_DIR, "review")
APPROVED_DIR = os.path.join(AUDIT_QUEUE_DIR, "approved")
REJECTED_DIR = os.path.join(AUDIT_QUEUE_DIR, "rejected")

# 异常检测阈值
ANOMALY_TONE_THRESHOLD = 3.0  # Goldstein 绝对值 > 3 视为异常
ANOMALY_EVENT_SPIKE = 2.0  # 事件数突增 > 2倍视为异常
ANOMALY_MIN_EVENTS = 5  # 至少 5 个事件才触发分析

# GDELT 数据源（示例，实际应连接 PG）
GDELT_MOCK_PATH = os.getenv("GDELT_MOCK_PATH", "./data/gdelt_mock_48h.json")

# 日志
logging.basicConfig(
    level=getattr(logging, LOG_LEVEL),
    format="%(asctime)s - %(name)s - %(levelname)s - %(message)s"
)
logger = logging.getLogger("quick_take_autopilot")


# ============================================================
# 第一步：GDELT 数据拉取（此处为 PG 查询占位）
# ============================================================

def fetch_gdelt_events(window_hours: int = 48) -> pd.DataFrame:
    """
    从 PostgreSQL 拉取最近 N 小时的 GDELT 事件。
    实际部署时替换为 PG 查询。
    """
    logger.info(f"Fetching GDELT events for last {window_hours} hours...")

    # 🔴 生产环境：替换为真实 PG 查询
    # 示例：SELECT * FROM gdelt_events WHERE event_date > NOW() - INTERVAL '48 hours'
    # 此处用模拟数据占位

    if os.path.exists(GDELT_MOCK_PATH):
        with open(GDELT_MOCK_PATH, 'r') as f:
            data = json.load(f)
        return pd.DataFrame(data)

    # 若无模拟数据，生成示例数据
    logger.warning("No GDELT data found. Generating mock data for demo.")
    np.random.seed(42)
    dates = pd.date_range(end=datetime.now(), periods=30, freq='H')
    mock_data = {
        'event_date': dates,
        'actor1_code': np.random.choice(['CHN', 'USA', 'RUS', 'JPN', 'PHL', 'UKR', 'IRN', 'ISR'], size=30),
        'actor2_code': np.random.choice(['None', 'USA', 'CHN', 'RUS', 'UKR', 'PHL', 'IRN'], size=30),
        'event_code': np.random.choice(['010', '051', '040', '043', '042', '190', '020'], size=30),
        'goldstein_tone': np.random.uniform(-6, 6, size=30).round(2),
        'num_mentions': np.random.randint(1, 50, size=30),
    }
    df = pd.DataFrame(mock_data)
    df['event_date'] = pd.to_datetime(df['event_date'])
    return df


# ============================================================
# 第二步：异常检测
# ============================================================

def detect_anomalies(df: pd.DataFrame) -> List[Dict]:
    """
    检测异常信号，返回候选事件列表。
    """
    logger.info("Detecting anomalies...")
    anomalies = []

    # 1. 情绪异常：goldstein_tone 绝对值超过阈值
    tone_anomalies = df[abs(df['goldstein_tone']) > ANOMALY_TONE_THRESHOLD]
    for _, row in tone_anomalies.iterrows():
        anomalies.append({
            'type': 'tone_spike',
            'event_date': row['event_date'],
            'actor1': row['actor1_code'],
            'actor2': row['actor2_code'],
            'event_code': row['event_code'],
            'goldstein_tone': row['goldstein_tone'],
            'num_mentions': row['num_mentions'],
            'reason': f"情绪异常: {row['goldstein_tone']}"
        })

    # 2. 事件密度异常：按小时/国家分组检测突增
    hourly_counts = df.groupby([df['event_date'].dt.floor('H'), 'actor1_code']).size().reset_index(name='count')
    if len(hourly_counts) > 1:
        # 计算每小时平均，判断突增
        avg_count = hourly_counts['count'].mean()
        spikes = hourly_counts[hourly_counts['count'] > avg_count * ANOMALY_EVENT_SPIKE]
        for _, row in spikes.iterrows():
            anomalies.append({
                'type': 'event_spike',
                'event_date': row['event_date'],
                'actor1': row['actor1_code'],
                'actor2': None,
                'event_code': None,
                'goldstein_tone': None,
                'num_mentions': row['count'],
                'reason': f"事件密度突增: {row['count']} 条/小时 (平均 {avg_count:.1f})"
            })

    logger.info(f"Detected {len(anomalies)} anomalies.")
    return anomalies


# ============================================================
# 第三步：生成事件快评（调用 DeepSeek）
# ============================================================

def generate_quick_take(anomaly: Dict, context_df: pd.DataFrame) -> str:
    """
    对单个异常事件生成快评。
    """
    logger.info(f"Generating quick take for anomaly: {anomaly['reason']}")

    # 提取上下文（该 actor 最近 48h 的统计数据）
    actor = anomaly.get('actor1')
    if actor:
        actor_events = context_df[context_df['actor1_code'] == actor]
        total_events = len(actor_events)
        avg_tone = actor_events['goldstein_tone'].mean() if total_events > 0 else 0
        main_actors = actor_events['actor2_code'].value_counts().head(5).to_dict()
    else:
        total_events = len(context_df)
        avg_tone = context_df['goldstein_tone'].mean()
        main_actors = {}

    # 构建 prompt
    prompt = f"""
你是一个 ConStruct Lab 的结构分析员。请根据以下 GDELT 异常信号，生成一篇 500-800 字的事件快评。

【异常信号】
- 类型: {anomaly['type']}
- 时间: {anomaly['event_date']}
- 主体: {anomaly.get('actor1', '未知')}
- 对象: {anomaly.get('actor2', '无明确对象')}
- 事件代码: {anomaly.get('event_code', '未知')}
- 情绪分数: {anomaly.get('goldstein_tone', 'N/A')}
- 异常原因: {anomaly['reason']}

【上下文数据】
- 该主体 48h 总事件数: {total_events}
- 48h 平均情绪: {avg_tone:.2f}
- 主要互动对象: {json.dumps(main_actors, ensure_ascii=False)}

请按以下结构输出（Markdown 格式）：

## [标题：一句话概括事件 + 结构判断]

### 1. 事件事实
（1-2句：发生了什么？基于 GDELT 数据描述）

### 2. 结构锚定
（3-5句：该事件触发了哪个主体的哪个 Identity/方法/恐惧？）

### 3. 历史参照
（2-3句：COW/UCDP 历史数据中有无类似先例？）

### 4. 走向判断
（1-2句：在结构约束下，最可能的演化路径是什么？）

### 5. 反洗脑提示
（1句：别被哪种常见叙事忽悠？）

---
注意：
1. 不要使用"可能""也许"等模糊词，用结构推理代替猜测。
2. 每个判断必须锚定在数据上（即使数据是上下文中提供的）。
3. 如果缺乏足够数据，在末尾标注 [置信度: 中/低] 并说明原因。
"""

    # 调用 DeepSeek
    if not DEEPSEEK_API_KEY:
        logger.warning("DEEPSEEK_API_KEY not set. Returning template only.")
        return f"# 事件快评草稿（待 API 调用）\n\n{anomaly['reason']}\n\n请设置 DEEPSEEK_API_KEY 以生成完整内容。"

    headers = {
        "Authorization": f"Bearer {DEEPSEEK_API_KEY}",
        "Content-Type": "application/json"
    }
    payload = {
        "model": "deepseek-chat",
        "messages": [
            {"role": "system", "content": "你是一个结构驱动的地缘政治分析员，擅长用 Identity-Method-Fear 框架解读国际行为。"},
            {"role": "user", "content": prompt}
        ],
        "temperature": 0.3,
        "max_tokens": 2000
    }

    try:
        response = requests.post(DEEPSEEK_API_URL, headers=headers, json=payload, timeout=30)
        response.raise_for_status()
        result = response.json()
        content = result['choices'][0]['message']['content']
        return content
    except Exception as e:
        logger.error(f"DeepSeek API call failed: {e}")
        return f"# 事件快评生成失败\n\n错误: {str(e)}\n\n异常信息: {anomaly['reason']}"


# ============================================================
# 第四步：写入审计队列
# ============================================================

def write_to_audit_queue(content: str, anomaly: Dict) -> str:
    """
    将生成的内容写入审计队列，返回文件路径。
    """
    # 确保目录存在
    for d in [AUDIT_QUEUE_DIR, DRAFTS_DIR, REVIEW_DIR, APPROVED_DIR, REJECTED_DIR]:
        os.makedirs(d, exist_ok=True)

    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    actor = anomaly.get('actor1', 'UNKNOWN')
    filename = f"quick_take_{actor}_{timestamp}.md"
    filepath = os.path.join(REVIEW_DIR, filename)

    # 元数据头
    full_content = f"""---
# 审计元数据
generated_at: {datetime.now().isoformat()}
actor: {actor}
event_date: {anomaly.get('event_date', '')}
anomaly_type: {anomaly['type']}
goldstein_tone: {anomaly.get('goldstein_tone', 'N/A')}
num_mentions: {anomaly.get('num_mentions', 'N/A')}
status: pending_review
reviewed_by: 
reviewed_at: 
verdict: 
---

{content}
"""

    with open(filepath, 'w', encoding='utf-8') as f:
        f.write(full_content)

    logger.info(f"Quick take written to: {filepath}")
    return filepath


# ============================================================
# 主程序
# ============================================================

def main():
    parser = argparse.ArgumentParser(description="ConStruct Lab 事件快评自动化")
    parser.add_argument("--mode", choices=["detect_only", "full"], default="full",
                        help="detect_only: 只检测不生成 | full: 检测并生成快评")
    parser.add_argument("--hours", type=int, default=48,
                        help="分析窗口（小时）")
    args = parser.parse_args()

    logger.info("🚀 ConStruct Lab 事件快评自动化启动")

    # 1. 拉取数据
    df = fetch_gdelt_events(args.hours)
    logger.info(f"Fetched {len(df)} events.")

    if len(df) < ANOMALY_MIN_EVENTS:
        logger.warning(f"Too few events ({len(df)} < {ANOMALY_MIN_EVENTS}). Skipping.")
        return

    # 2. 检测异常
    anomalies = detect_anomalies(df)

    if not anomalies:
        logger.info("No anomalies detected. Exiting.")
        return

    # 3. 生成快评
    if args.mode == "full":
        for i, anomaly in enumerate(anomalies[:5]):  # 限制单次最多 5 条，防止 API 过载
            logger.info(f"Generating quick take {i+1}/{min(len(anomalies), 5)}...")
            content = generate_quick_take(anomaly, df)
            filepath = write_to_audit_queue(content, anomaly)
            logger.info(f"Saved: {filepath}")
    else:
        logger.info("Detect-only mode. Anomalies found:")
        for a in anomalies:
            logger.info(f"  - {a['reason']}")

    logger.info("🏁 事件快评自动化完成")


if __name__ == "__main__":
    main()
```

## 四、质量标准

所有贡献必须满足以下四条：

| 标准 | 说明 | 不合格示例 |
|------|------|------------|
| **数据锚定** | 判断能追溯到 GDELT/COW/UCDP | “中国在南海很强势” → ❌ 缺少数据支撑 |
| **结构驱动** | 从 Identity-Method-Fear 推导 | “俄罗斯因为好战所以打仗” → ❌ 用标签代替结构 |

| **不确定性标注** | 区分高/中/低置信度 | “中国不会攻击美国军舰” → ❌ 应标注 [高/中/低，依据：…] |

## 五、社区准则

1. **数据优先于立场**：你可以有观点，但必须有数据支撑。
2. **结构优先于标签**：用 Identity-Method-Fear 框架分析，不用“流氓国家”、“极权”、“民主灯塔”等标签代替分析。
3. **可以不同意，但要说明理由**：如果你不同意某份报告或条目，请用数据或结构逻辑反驳，而不是情绪或立场。
4. **尊重时间线**：历史事件用 COW 数据，不要用“自古以来”这类无时间锚点的表述。
5. **承认不确定性**：如果数据不足以支撑判断，标注为“低置信度”并说明原因，而不是强行给结论。
