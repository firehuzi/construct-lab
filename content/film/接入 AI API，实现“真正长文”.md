接入 AI API，实现“真正长文”
这是最能发挥你“结构诊断”价值的路径。骰子生成的结构化 JSON（framework / problem / mechanism / collapse / context / object）本身就是极好的 Prompt 骨架。

你可以这样设计：

保留现有掷骰逻辑，掷出的 6 个维度 + interpNotes 作为“结构化输入”。

增加一个“生成长文”按钮（或替代现有短评）。

调用 DeepSeek / 通义千问 / Claude API（或使用浏览器内置的 window.ai 实验性 API），发送如下格式的 Prompt：

系统角色：你是一位资深电影评论家，擅长模仿 [戴锦华 / 罗杰·伊伯特 / 宝琳·凯尔] 的写作风格。
任务：根据以下电影分析结构，写一篇 400 字左右的深度评论。
电影：{当前电影名}
理论框架：{framework}
核心问题：{problem}
分析对象：{object}
运作机制：{mechanism}
宏观语境：{context}
崩塌方向：{collapse}
结构诊断（必须作为核心论点）：{interpNotes}
要求：开篇点出诊断，中间层层递进论证，结尾回扣电影本体。不要罗列术语，要融入到行文里。

这样生成出来的长文，不仅逻辑自洽，而且风格化极其明显。你可以预设 5 种知名风格按钮（戴锦华、罗杰·伊伯特、宝琳·凯尔、周黎明、齐泽克式哲学随笔），只需修改 Prompt 中的“模仿对象”即可。

✅ 优点：质量极高、风格区分度强、内容几乎无限变化。
❌ 缺点：需要用户自备 API Key（或服务端代理），有微小延迟和 API 调用成本（但单次成本极低，约 0.01~0.03 元）。


你说到了这个工具最致命的短板——内置数据库再大（哪怕 1000 部），也永远追不上用户的输入。而一旦查不到，回退到纯随机，整个“结构解读”的幻觉就瞬间崩塌了。

要解决这个问题，“前置的电影语言结构化数据提取”是唯一正确的方向。但关键区别在于：纯前端 JS 绝对做不到这一点（没有 AI 理解力，你无法从“《肖申克的救赎》”这几个字中推理出“监狱、希望、体制化”）。

所以，必须引入 LLM（大语言模型）API 来做“结构化提取”。

好消息是：这个提取动作，可以和你上一轮提到的“长文生成”共用一个 API 调用，实现“一鱼两吃”——既解决了新电影的适配问题，又生成了风格化长文。

🔧 关键：如何设计“结构化提取”的 Prompt？
这个 Prompt 的目标是强行让 AI 输出一个和 FILM_DB 条目结构完全一致的 JSON，这样你的掷骰加权逻辑 一行代码都不用改。

Prompt 示例（可直接用于 DeepSeek / GPT 等）：

系统指令：
你是一位电影语言分析专家。请为电影《{电影名}》提取结构化数据，严格按以下 JSON 格式返回，不要输出任何其他内容。

json
{
  "themes": ["主题1", "主题2", "主题3", "主题4", "主题5"],
  "conflicts": ["对抗关系1（用vs连接）", "对抗关系2"],
  "spaces": ["核心空间1", "核心空间2", "核心空间3"],
  "motifs": ["重复出现的意象/物件1", "意象2", "意象3"],
  "theoryFit": {
    "拉康": 0-5之间的整数,
    "齐泽克": 0-5,
    "福柯": 0-5,
    "鲍德里亚": 0-5,
    "德里达": 0-5,
    "本雅明": 0-5,
    "巴特勒": 0-5,
    "德勒兹": 0-5,
    "巴特": 0-5,
    "阿多诺": 0-5,
    "马克思": 0-5,
    "弗洛伊德": 0-5
  }
}
约束：

themes 必须是从电影主题中抽象出的学术概念（如“异化”、“规训”、“欲望的流动性”）。

conflicts 必须使用“A vs B”格式。

theoryFit 表示该电影与对应理论家的契合度，5为极度契合，0为无关。

只输出 JSON。

🎯 如何与现有代码无缝对接？
你只需要在 getFilmData(input) 函数中增加一个 “未命中时的 AI 回退”逻辑：

javascript
async function getFilmDataWithAI(input) {
  // 1. 先查本地库
  let data = getFilmData(input); // 你原来的同步函数
  if (data) return data;

  // 2. 未命中，检查是否有缓存的 AI 结果
  const cacheKey = `film_${input}`;
  const cached = sessionStorage.getItem(cacheKey);
  if (cached) return JSON.parse(cached);

  // 3. 调用 AI 提取
  const aiResult = await callAIForStructuredData(input);
  // aiResult 就是和 FILM_DB 条目一模一样的对象
  
  // 4. 缓存起来（本次会话有效）
  sessionStorage.setItem(cacheKey, JSON.stringify(aiResult));
  return aiResult;
}
⚠️ 因为 rollDice() 是同步执行的，现在需要将它改为 async，或者在点击掷骰时先 await 提取数据。

🔄 与“风格化长文”的协同
这个“结构化提取”和上一轮你说的“长文生成”完全可以合并为一次 API 调用，节省成本和时间：

方案 1（两次调用，更精准）：先调提取 API 拿 JSON → 前端加权掷骰 → 再调长文 API（把掷出的 6 个维度 + 提取的 JSON 一起喂给 AI）。

方案 2（一次调用，更高效）：直接让 AI 一次性完成“结构提取 + 长文生成”。

在长文生成 Prompt 中，除了要求写评论，还强制要求在最前面以特定格式附上结构化 JSON。前端解析这个 JSON，用它来做后续的链式展示和置信度计算，同时直接把长文展示在页面上。
