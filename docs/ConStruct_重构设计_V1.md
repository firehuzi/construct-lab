## 一、为什么要重构（诊断，带证据）

不是「有几个 bug」，是**没有设计**的必然结果。以下缺陷全部来自 2026-10 这一轮的实测，不是印象：

### 病型 0（最根本）：核心资产根本不在版本控制里

实测（`git ls-files` 逐目录比对）：

| 目录 | 文件数 | 被 git 跟踪 |
|---|---|---|
| `docs`（全部立项书／路线图／设计文档） | 73 | **0** |
| `actors` | 84 | **0** |
| `content` | 143 | **0** |
| `ConStruct_Archive`（47 档案） | 79 | **0** |
| `CWKB_Vault` | 43 | **0** |
| `construct-stack`（数据栈） | 3166 | **0** |
| **合计** | **3588** | **0** |

**根目录有一个【空的 `.git` 目录】** —— 所以根不是仓库，`git` 直接报
`fatal: not a git repository`。只有 `construct-engine`（508 文件，remote = `firehuzi/construct-lab`）
和 `construct-lab-site` 有仓。

**⇒ 这一条解释了下面好几条**：两份同 title 的副本、`框架v3.0.html` 零命中却在清单里、
`CWKB_v3.0_source.txt` 与 `v3.0.txt` 字节相同 —— **没有版本控制，所以没人知道哪个是哪个，
也无法追溯谁在什么时候改了什么。** 「47 份档案」这个最强资产，目前**只存在于一块硬盘上**。

### 病型 1：声明与产物从不互相对照

### 病型 2：设计的东西没建，或建了没接

| 实例 | 事实 |
|---|---|

| **底盘六层**（地理→经济→历史→文化→族群→创伤锚点） | 是**另一条线**（地缘推演台）的结构；**两条线从未合并**，工具里「地理 0 处、族群 0 处」 |

### 病型 3：词汇与版本不统一

* 47 份档案与工具**不共享一套词汇**，且长期**没有导入路径**（审计 F20 才补上）
* **三套版本号并行**；`v2.1.html` 内部标 v2.2
* **两份 `<title>` 完全相同的文件，内容差 11 KB** —— 本轮我差点拿错当基座
* `CWKB_v3.0_source.txt` 与 `CWKB v3.0.txt` **字节完全相同**（同一份两个名字）

### 病型 4：口径不对题（做检查的人自己也会犯）

本轮**我的审计器自己犯了三次同型错误**，全部记在代码注释里：

1. 只看 `state.` 字面量 → 层里用的是字符串路径（`updateState('id','path')`）⇒ 逐层全显示 0
2. `Object.entries(state.fears)` 是**动态读** ⇒ 差点把「诊断的核心输入」（L8 四个恐惧）误报成「只写不读」
3. 切分正则要求 `layer-icon` 后紧跟 `>`，而 L11 的 span 带 `style` ⇒ **L11 整块被并进 L10**，我据此得出「工具里没有 L11」的**错结论**

**⇒ 结论：摸石头过河是有效的探索方式，但探索完必须回头定图纸。现在回头。**

## 二、目标规格

```
输入：一件地缘政治事件（当前或过去）
      { 时间, 描述, 涉及主体（可留空由系统识别）, 出处 }

输出：一份分析报告
      { 主体诊断,
        路径推演（若干条可能路径，每条带触发条件／早期信号／失效条件）,
        排除断言（不可能路径，每条带证伪条件与窗口）,
        追溯表 }
```

**「排除」与「推演」是同一个判断的两面，必须同时产出**：

| 只做一半 | 结果 |
|---|---|
| 只说「不可能」 | **病人** —— 不可证伪的断言不携带信息（本轮实测：三条真实记录里两条的判据填成了理由或预测） |
| 只说「可能 A/B/C」 | **廉价** —— 什么都能说，无从检验 |
| **「A/B/C 可能，D/E 不可能」** | **一个有边界的判断** —— 而且**两个方向都可核**（见 §四 的核验） |

**这句话的分量在「端到端」**：它要求**整条链都通**，而不是像现在这样「每一环各有各的完成度」。

## 三、阶段划分

| 阶段 | 做什么 | 判据 |
|---|---|---|
| **B（先）** | **分析者判断 ＋ 系统强制结构**：系统负责识别主体、加载档案、预填、逼你写证伪条件与窗口、累积成账；判断由分析者下 | 见 §七 验收标准 |
| **A（后）** | **自动推导**：把 B 中被证明有效的步骤编码 | 见 §八 闸门 |

**为什么 B 必须先跑通**：B 是 A 的规格书。**每一次手工判断里，有价值的步骤成为自动化候选，没价值的直接砍。** 先自动化一个没验证过的流程，只会把分歧藏起来。

**并且有一条证据支持这个次序**：本轮所有**全自动**的尝试都失败了（八维的轴到数据天花板、GDELT 读出口无效应、选择偏倚把 ρ 从 +0.507 打到 +0.263）；而**手工的结构化判断是对的**（克里米亚那次：路径预测命中、排除断言成立、判据修正后合格）。

## 四、一条管道（B 阶段的全部工作）

**核心规矩：每一段都必须产出【结构化产物】，不能只有文字。**

| 段 | 输入 | 输出 | **怎么核它真的通了** |
|---|---|---|---|
| **S1 事件登记** | **原报道文本**（粘贴／抓取）＋ **出处**（URL／数据库 id／报道时间）＋ 事件日期 | 事件记录 ＋ 涉及主体列表 | 三条**保真**要求（见下 §四之一） |
| **S2 主体加载** | 主体名（来自 S1，**可能是任何东西**） | ① 已有档案的预填 ② **新主体的建档初稿** ③ 每项带出处 | 见 §四之二（三层：识别分类／新建档／框架形式化） |
| **S3 结构诊断** | 预填 ＋ 分析者修订 | 11 层状态 ＋ 诊断结论 ＋ SUL | ① **L5 四项全进诊断**；② **反馈回路要么真算、要么从标题撤掉「闭环」** |
| **S4 判断登记** | 事件 ＋ 诊断 | **三类产物**：① 路径推演（若干条可能路径：触发条件／早期信号／失效条件）② 排除断言（证伪条件＋窗口）③ `construct-run-v1` 记录 | **三方向可核**：<br>· 排除断言：被排除的路径**发生了** ⇒ 证伪<br>· 排除断言：判据不对题／无窗口 ⇒ 不携带信息<br>· **路径推演：若干条可能路径【一条都没发生】** ⇒ **路径空间错位**（记进预测坟场） |
| **S5 报告生成** | S3 ＋ S4 | 报告（Markdown / 公众号 HTML） | **报告里每个结论都能追到 S3/S4 的某个字段** |
| **S6 归档累积** | 报告 ＋ 记录 | 账（排除断言）＋ 历史（推演记录）＋ 坟场 | 可复跑对账；**内容指纹防过期**（结论不许悄悄失效） |

**管道里已经能用的零件**（本轮实测可跑）：

* **S4 的路径推演【已经有一半】**：历史回溯工具的 `state.paths = [{label, probability, why}]`
  —— 已经是「若干条可能路径 ＋ 概率 ＋ 理由」。**缺的是每条的「触发条件／早期信号／失效条件」**，
  现在只有一个自由文本的 `why`，而**自由文本无法核**。
* S4／S6：`exclusion_ledger.py`（31 条自证）／`claims_ledger.py`（28）／`build_tool.py`（29）／`audit_layers.py`（10）
* S2：`loadArchive` ＋ 47 档案（**L2–L8 字段齐备**，抽样 3 份全中）
* S5：`genGzhHTML` / `genSubstackMD` / `exportReport` / `publish_article.py`

**管道里缺的**：

* **S1**（没有「输入一件事件」的入口 —— 现在是让你从零填 11 层表单，**这与原始意图已经不是一个东西**）
* **S2 的出处字段**（档案里有内容，但没有「哪一行」的可追标记）
* **S3 的 L5 接线 与 反馈回路**

## 四之一、S1 的保真要求（三条，都可核）

**用户的原话：「不接事件输入就无法保真」。** 这句话指向一个具体的失效模式：
**手打的事件是分析者记忆里的版本** —— 从 S1 就失真，后面五段再准也没用。

| # | 要求 | 怎么核 |
|---|---|---|
| **F1** | **事件输入必须是【原文】而不是【复述】** | 每条事件带原始报道文本 ＋ 出处 URL／数据库 id。**允许粘贴，不允许转述。** |
| **F2** | **S1 不许出现解读** | S1 只放「发生了什么 ＋ 出处 ＋ 时间」。**禁止**在 S1 写「这意味着…」「这是为了…」—— 解读归 S3／S4，那里有出处和可证伪性要求。机器可查：S1 字段里出现因果词（因为／为了／意味着／目的在于）即拒收。 |
| **F3** | **时间锁定（历史事件必填）** | 只放**事件发生时已知的信息**。这是历史回溯工具已验证的机制（`renderTimeLock`：任何事后才知道的信息——哪怕你知道——不能用于判断）。 |

**⇒ 而 F1／F3 直接要求【外部事件数据】**：

* **UCDP GED v26.1 已落地**（417,968 事件，1992–2025，`construct-stack/scripts/ged261-csv.zip`）
* **GDELT 采集器已有**（`collect_gdelt.py`）——**但从没接进工具**
* **COW 时间线已有**（`actor_timelines/`，29 文件）

**这些零件存在却没接 —— 所以 F1／F3 现在做不到，只能手打。这就是「不接外部数据不现实」的具体含义。**

## 四之二、S2 的三层：主体不只那 47 个

**用户的要求：「在现有主体基础上建立主体框架并优化；需要实现现有主体之外的主体也能够分类；需要和数据层协同保真分析判断」。**

**现在的 S2 有一个硬边界**：只能从 47 份档案里挑一个。而**一件事件牵涉的主体，可能根本不在那 47 个里** —— 新的组织、派系、公司、个人。

**这不是边缘情况**：八维审计里 **企业/组织 占了 46 个主体中的 25 个**，而框架对它们**没有测量构造**。同类缺口。

### S2a 主体识别与分类

```
输入：S1 事件里提到的主体名（任何东西）
输出：{ 主体 id 或 新建 id, 主体类型（国家／国际组织／企业／武装派系／个人／其他）, 分类依据 }
核  ：① 在 47 档案里 → 加载，进 S2c 校验
      ② 不在 → 走 S2b 新建档
```

### S2b 新主体建档（关键能力）

```
输入：主体名 ＋ 事件上下文（S1 的原文）
输出：一份建档初稿（L2–L8 的初值 ＋ 每项的出处）
```

**三条硬规矩**：

| # | 规矩 | 为什么 |
|---|---|---|
| **N1** | **每个字段必须带出处**，且出处只能来自三个地方：**数据层记录**（UCDP／COW／GDELT 里的实际条目）、**事件原文**、**已有档案的显式引用** | 不许「凭常识填」。凭常识填的东西，与「八维值域文档称代码真相」是同一个病 |
| **N2** | **无法判定的字段必须标【未知】，不许给默认值** | 工具的默认值是 3，而 `createRatingButtons` 把 1-3 硬编码为 active ⇒ **默认值会被伪装成诊断结论**（这正是审计 F2 修过的病） |
| **N3** | 新主体建档后**必须回头补进档案库**，且标明**它是自动初稿、未经人工确认** | 否则 47 份档案会分裂成「人工的」和「机器生成的」两族，而没人知道哪份是哪份 |

### S2c 主体框架的形式化（用户说的「建立主体框架并优化」）

**把分类维度从「47 份档案里的字段」变成「可对任意主体施加的分类器」。** 每个维度必须写清两件事：

```
维度：锁定模式（7 式：互锁／冻结／锚定／交易／整合／摆荡／赎罪）
  判据：凭什么把它归到这一类？        ← 现在只存在于 47 个档案的举例里
  反例：什么情况下【不】归这一类？     ← 现在完全没有
```

**没有「反例」的分类维度是不可证伪的** —— 它会把任何主体都收进去。**这是本轮反复出现的病型在分类学上的版本。**

**而且这里要处理一处已知的词汇分裂**（见 §五）：47 档案用了 **14 种连续性用词**，而工具只认 **3 类**（主体型／秩序型／混合型）。形式化时必须给出**对照表**，并且沿用审计 F20 已验证的模式：**枚举（工具参与推理）＋ 原文（只显示）并存**。

### 「和数据层协同保真分析判断」的确切含义

这一句最容易被做成错的，所以要写死边界：

> **数据层能告诉你一个主体【做了什么】，不能告诉你它认为自己是【谁】。**
> **而框架的核心是后者（Identity）。**

因此「协同」**不是「用数据代替判断」，是「用数据约束判断」**：

| 数据层能给 | 数据层不能给 |
|---|---|
| **证伪**：数据里它从没做过 X，却把它归到「以 X 为核心恐惧」的那一类 ⇒ 该分类有问题 | **推出**：数据里它做过 X ⇒ 所以它属于某类（**这是归纳，不是推导**） |
| **锚定存在性**：它在 UCDP 里 ⇒ 它是冲突当事方（直接关系到「核心恐惧」）；在 COW 里 ⇒ 它被承认为主权国家 | **自我定义**：它认为自己是谁 —— 这只能从它的**叙事文本**读，而那是分析者的判断 |
| **排除**：它在任何数据集里都零命中 ⇒ 至少标「数据层无记录」 | **补全**：没有记录 ≠ 没有行为（本轮我三次栽在「把查不到当成没有」） |

**⇒ 落到可核的形式，就是 S2b 的 N1：每个字段的出处必须能被指出来。** 数据层提供的出处是「某数据集某条记录」，事件原文提供的出处是「原文第几段」，**两者都能核；「凭常识」不能核，所以不许。**

**这一步和本轮已建的东西直接接得上**：`ucdp_readout.py` 已经能从数据里**自导出自家的 GW 码**、把主体名映射成码、并统计双边事件 —— 也就是说，**「这个主体在冲突数据里存不存在、做了什么」这件事，机器已经能回答了**。

## 六、砍掉清单（不做完不开始）

**0. 【最优先】给核心资产上版本控制。** 3588 个文件（47 档案／CWKB／全部文档）目前不在任何仓库里，
只存在于一块硬盘上。**在重构之前先做这一件** —— 否则重构过程本身也会重演「两份同 title」
「哪份是新的」的老问题。
建议：把 `docs`／`actors`／`ConStruct_Archive`／`CWKB_Vault`／`content` 纳入 `construct-lab`
（`construct-stack` 的 3.1 GB 数据单独处置，不入库）。

1. **两份同 `<title>` 的副本** —— `content/published/地缘政治分析框架v2.1.html`（70 KB）标「（旧快照）」或删。判据：基座含 `archivePick`，它没有。

## 七、验收标准（可核，不是形容）

B 阶段算跑通，当且仅当以下**全部**成立：

1. **端到端**：只给一件事件，**不改代码**，产出报告
2. **可追**：报告里每个结论都能追到「某个字段 + 某个出处」
3. **可证伪**：① 所有排除断言都有**证伪条件 ＋ 窗口**；② 所有可能路径都有**触发条件 ＋ 失效条件**；
   缺一即**阻止出报告**（不是警告，是阻止）
4. **可复现**：同一事件、同一输入，两次跑**字段级可比**（不要求字面相同）
5. **可累积**：每次跑完账 **+1 条**，且账能复跑对账（`--ingest` ＋ 漂移闸门）
6. **有时限**：单次「事件 → 报告」≤ N 分钟。**N 由第一次实测定，不由现在猜。**
7. **可交付他人**：把工具与输入给另一个人，**他能跑出同形状的报告** —— 否则这不是系统，是个人风格
8. **双向可核**：**排除**（被排除的路径发生了 ⇒ 证伪）与**推演**（若干可能路径一条都没发生 ⇒ 路径空间错位）
   两条检查都要能真的亮起来 —— 本轮已为排除方向建了阈值判定与自证，推演方向尚未建

## 八、B → A 的闸门

**B 跑通 ≥ 10 次之后**，才允许启动 A。届时按以下规则定自动化候选：

| 指标 | 含义 | 用途 |
|---|---|---|
| **人工耗时占比** | 每一步花的时间 | 占比高的优先 |
| **判断一致率** | **两个人独立走同一事件**，同一字段给同一答案的比例 | 一致率高才可自动化 |

**硬规矩：一致率低的步骤【不许】自动化。** 那是把分歧藏进代码里 —— 而分歧恰恰是最需要暴露的东西。

## 九、非目标（明确不做）

* **不做【单点预测】** —— 不给单一结论、不给点估计概率（「特朗普会赢，72%」）。
  **但这不是「不做推演」**：报告**必须**给出**若干条可能路径**，每条带触发条件／早期信号／失效条件。
  区别在于：**单点预测把不确定性藏在一个数字里；路径推演把它摊开成一组有条件的、可核的路径。**
  （本轮实测支持前者不可做：所有全自动量化尝试都撞上「设不出阈值／选择效应」，
  而手工的结构化判断是对的。）
* **不做跨域**（金融／社会／影视）—— 在地缘跑通之前。第 4137 行那句「地缘分析、电影分析、
  刀具数据库都可以成为不同训练域」是**终局**，不是下一步
* **不接【无出处】或【无法追溯】的数据** —— 但**必须接事件数据**（S1 的 F1／F3 要求它，
  而「不接事件输入就无法保真」）。规则是**每个数据源先写一张「口径卡片」**：
  它是什么／覆盖什么／更新周期／已知缺陷／口径与我们的字段是否对得上。
  **这是本轮「口径对账」的教训** —— 数据是真的但不对题，比没有数据更危险。
* **不加新层** —— 工具已经有 13 个层块，先把 L5 和反馈回路修好

## 十一、B 阶段是【分步开发】，不是一次性交付

> **用户对 S3／S4 的定性（2026-10-02）**：
> **「S3 基本就是目前工具的结构优化」**；**「S4 还有很多缺口」**。
