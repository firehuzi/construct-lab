## 两个架构决定，以及为什么

### 1. 板块② 走 iframe，不合并 JS

**两个工具都声明 `state`**（诊断是 `const state =`，回溯是 `let state =`）—— 硬冲突。
CSS 也冲突（回溯是深色主题，会覆盖诊断的配色）。
**⇒ iframe 完全隔离，零风险。** 代价：板块② 是独立文件，工具不再是「单文件全包」。
`check_built_tool.js` 里有断言钉住「两者同名 ⇒ 隔离是必需的」。

### 2. 引擎算 → 构建器内联 → 前端只显示

**判定逻辑全在引擎里。** 免得同一件事有两套口径 ——
这个项目已经吃过「版本号三处不一致」「两份同 title 不同内容」的亏。

数据必须内联（不能用 `fetch`），因为工具要能双击打开（`file://`），
而 `file://` 下浏览器不允许页面 fetch 同目录的 json（CORS）。

## 板块② 的两条硬规矩（工具的立身之本）

1. **证伪条件必填** —— 写的是「**它发生了 = 出现什么**」，不是理由、不是预测。
   缺它 ⇒ 断言不可证伪 ⇒ **不携带信息**。
2. **窗口必填** —— 没窗口只能说「尚未发生」。而**窗口决定真值**：
   「盟军入侵伊拉克」**1991 年成立**（联军停在边境）、**2003 年被证伪**（美英入侵）。
   **同一个断言，窗口不同，真假相反。**

## 已知缺口（下一步）

* **板块① 没有持久化**（`localStorage` 0 处）—— 进度 4/14，关掉页面就没了。
* **板块② 的记录要手工搬运**：导出 JSON → 放进 `data/exclusions/` → 重新构建，账才更新。
  工具不能直接写账（`file://` 无写权限）。**部署到 web.app 后可以考虑加后端通道。**
* **两份同 title 的副本仍未清理** —— 建议把 `content/published/地缘政治分析框架v2.1.html`
  改名或加「（旧快照）」标记，免得下次又拿错。
