## 二、关键决定：走轻栈，但把重栈的【字段设计】搬过来

**原方案的实现走重栈**：`PostgreSQL + TimescaleDB`（真相源）＋ `Neo4j`（知识图谱）＋ `n8n`（编排）＋ 双写 ＋ 每小时对账。
**⇒ 从未建过**（`db` 目录空）。

**而我们这一轮用 `JSON ＋ git ＋ 脚本` 做出了同一套纪律的轻量版，并且【真的在跑】**：
8 条依据存档 ／ 296 条自证 ／ 4 个独立案例 ／ 全部可复现。

| | 重栈（原方案） | **轻栈（本轮验证过的）** |
|---|---|---|
| 存储 | PG + TSDB + Neo4j | JSON ＋ git |
| 查询 | SQL / Cypher | 脚本 |
| 编排 | n8n | 脚本 / 手工 |
| 可溯源 | `(:Source)` 节点 ＋ 边 | `index.json` ＋ sha256 |
| 上手成本 | 高（docker-compose、双写、对账） | **低（已在跑）** |
| 规模上限 | 高（时序、图谱遍历） | **低（几十条依据可以，几万条不行）** |
| 适合 | 长期、多主体、大规模信号 | **B 阶段：先把判断流程跑通** |

**★ 判断：B 阶段走轻栈。**
**理由：原方案里最值钱的不是 PG/Neo4j，是那三条纪律 —— 来源分级 ／ 交叉印证 ／ 无静默默认值。**
**前两条我们缺，而它们是【字段设计】，不是【栈】。抄字段，不抄实现。**

**★ 但必须同时定死重栈的触发条件（见 §五 S0′）** ——
否则我们会一直用轻栈做到某一天撞墙，**而那时不知道是哪一天开始不对的。**

## 三、S1 的定义（整合后）

```
输入：一件事件（原文 ＋ 出处 ＋ 时间锁定）
  ↓
① 来源登记    给来源打级（P0–P3），reliability 进记录        ← 新增（抄原方案 §2）
② 事件登记    原文不许转述；拿不到就留空标 needs_human        ← 已有（case_skeleton）
③ 主体识别    在档案里？不在就显式标「无档案」                ← 已有
④ 判断登记    路径空间 ＋ 排除断言（《写法指南》管着）        ← 已有（query_gen 可辅助）
⑤ 核验        source（机器判）／evidence（人判＋存档）／队列   ← 已有（case_check）
⑥ 交叉印证    同事实 ≥2 独立源 ⇒ confidence↑；矛盾标出        ← 新增（抄原方案 §5.2）
  ↓
输出：construct-run-v1（顶层 paths/exclusions ｜ 依据带 sha256）＋ 可追的结论
```

**⇒ 六步里四步已有工具，缺的只有 ① 与 ⑥。**

## 五、分期（每期带跑通判据）

| 期 | 做什么 | 跑通判据 |
|---|---|---|
| **S1.0 · 入口** | 把 `case_skeleton` / `query_gen` / `archive_source` / `case_check` 串成一条命令 | **给一个双边对＋年份，一条命令出完整 `construct-run-v1`** |
| **S1.1 · 来源分级** | 抄原方案 P0–P3 ＋ `reliability`；`confidence` 能算 | 每条依据带分级，且 `confidence` 可复算 |
| **S1.2 · 交叉印证** | 抄原方案「≥2 独立源 ⇒ confidence↑；矛盾标 `contradiction`」 | **对已互证过的那条（P04①）能机器标出「2 源互证」** |
| **S1.3 · 同输入逐位相同** | `cellId` 式：canonical JSON → FNV；产物哈希 | **同一事件跑两次，哈希相同**（这就是《读数口径登记表》C2 那一格） |
| **S1.4 · 空目录** | CWKB 七个空目录：**要么填，要么撤** | 不留空目录 |
| **S0′ · 重栈触发条件** | 写死一条可核的线 | 如「依据 >5000 条」或「信号 >100 万条」⇒ 上 PG/Neo4j |

**依赖**：S1.0 → (S1.1 ∥ S1.2) → S1.3 → S1.4 ／ S0′ 随时可写。

## 六、照实记

1. **本计划没有写任何代码**，它只把一个决定（轻栈 + 抄字段）和一份分期写下来。
2. **S1.0 的「一条命令」是这一期唯一真正的工程量** —— 现有工具之间没有入口，**每次都要我手工串**。
3. **F1「原文」仍然要人补**（两个案例都留空未编）—— **本计划不解决它，也不假装解决。**
4. **重栈的三条纪律里，我们只有一条（无静默默认值）。** 另两条（分级、交叉印证）是这个计划的主体。
5. **⚠️ 七个空目录里 `Indexes` 最要紧** —— 设计里它是连接知识层与引擎的枢纽，**而它是空的**。S1.4 要处理它，但**怎么填需要另一次设计**，本计划不给答案。
