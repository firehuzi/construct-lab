# ConStruct Lab · B4 规格（S4 判断登记扩展）V1

> 日期：2026-10-02 ｜ 状态：**待评审**
> **B4 是六段里缺口最大的一段，而且它是 S5／S6 的输入** ——
> 「一条判断长什么样」定不下来，S5 不知道该渲染什么，S6 不知道该累积什么。
> **所以从 B4 起做，比从 S1 顺着做少返工。**

---

## 一、B4 要解决的问题（实测）

**现在的 S4 是什么**：历史回溯工具的 `state.paths = [{label, probability, why}]`
＋ `state.exclusions = [{excluded, criterion, window}]`，导出 `construct-exclusion-v1`。

**四个缺口**：

| # | 缺口 | 后果 |
|---|---|---|
| 1 | **路径推演只有 `why`（自由文本）** | **无法核** —— 三条真实记录里 `why` 全是散文，机器读不了 |
| 2 | **路径推演没有「什么算它发生了」** | **「若干条路径一条都没发生」这个检查无从建**（见 §三 检查 3） |
| 3 | **排除断言与路径推演是两套形状** | 同一个概念（可观察判据）写了两遍，口径必然分叉 |
| 4 | **判定逻辑在前端** | `criterionOverlap` 在 HTML 里、`ingest_state` 在 Python 里 —— **同一件事两处实现** |

**⇒ B4 要做的四件事，对应这四个缺口。**

---

## 二、核心决定：把「可观察判据」抽成两者共用的字段

**这是 B4 最重要的一个设计决定。**

**排除断言**要回答：**「什么算它发生了？」**（发生了 ⇒ 我错了）
**路径推演**要回答：**「什么算它发生了？」**（发生了 ⇒ 我对了）

**两句话是同一个问题** —— 只是一条要**证伪**、一条要**确认**。

**所以不该有两套字段。** 统一为：

```json
{
  "observable": {
    "object":  "谁/什么被观察",          // 必填
    "indicator": "看到什么算发生",        // 必填
    "threshold": null,                   // 可选：量化门槛（如「≥1 起空袭」）
    "source": null                       // 可选：从哪个数据源看（如 "UCDP:GED"）
  },
  "window": {"from": "1991-01-15", "to": "1994-01-15"}   // 必填
}
```

**为什么这样切**：

* **`object` + `indicator` 是自然语言，人必须写** —— 这是判断
* **`threshold` + `source` 是能不能自动判的分界**：
  **两者都有 ⇒ 机器可判；缺任一 ⇒ 进「待人工判定」队列**（见 §五）
* **`window` 必填** —— 本轮已经证明「窗口决定真值」（盟军入侵伊拉克：1991 成立、2003 被证伪）

## 三、三条检查（B4 的全部验收对象）

> **★ 本节已按一次真跑修正（见《路径空间试写_克里米亚》）。四处改动：**
> **① `stages[]` 每阶段加 `discriminating`，判定只数区分性阶段；**
> **② 判定单位从「路径」改为「可判点」，且路径级与可判点级两个读数都报；**
> **③ 每条路径必填 `rules_out`（它排除了什么）；**
> **④ `exhaustive_claimed` 是装饰性标记 ⇒ 改成可核形式。**

### 检查 1：排除方向 —— 被排除的路径**发生了** ⇒ 证伪

**已有**：`WAR_DEATH_THRESHOLD = 1000`（锚在 UCDP 自己的战争定义上）＋ `check_ucdp_war`
＋ 双边对数据。**自证已能双向亮**（IN-PK 未达门槛 ⇒ 尚未被证伪；RU-UA 达门槛 ⇒ 证伪）。

**B4 要补**：把它从「只有 `ucdpwar:` 一种核对」扩展到**多种核对类型**，且**类型可声明**：

| 核对类型 | 判什么 | 数据源 | 状态 |
|---|---|---|---|
| `ucdpwar:<A>-<B>:<年>` | 双边年度战斗死亡 ≥ 阈值 | UCDP GED（已落地，到 2025） | ✅ 已有 |
| `ucdp:<A>-<B>:<年>` | 双边事件数 ≥ 阈值 | 同上 | ✅ 已有 |
| `cow:<A>-<B>:<年>` | 时间线里的 WAR/MID 事件 | `actor_timelines/`（COW，**止于 2014**） | ⚠️ 已有但窗口覆盖不到 2020+ |
| `fact:<主张>` | 公开记录（如「伊朗是否承认以色列」） | **无** | ❌ 缺 —— 必须进「待人工判定」 |

**★ 硬规矩（沿用本轮已建的自证）**：**数据覆盖不到窗口 ⇒ 判「数据不够」，不许判「尚未被证伪」。**
（本轮我在 COW 上栽过一次：骨架止于 2014，而窗口自 2020 起，「自 2020 年起未见」是空的。）

### 检查 2：判据质量 —— 缺判据／判据不对题／无窗口 ⇒ **不携带信息**

**已有**：`criterion_overlap()`（中文字符二元组）＋ `ingest_flags()`（多问题一起报）

**B4 要补**：

* 判据从**一个自由文本**升级成 §二 的 `observable` 结构 ⇒
  **`object` 或 `indicator` 为空即缺判据**（比「整栏非空」更硬）
* **`object` 必须出现在事件的涉及主体或路径内容里** —— 这是「对不对题」的结构化版本，
  比词面重叠可靠（词面重叠是粗筛，会漏语义等价）

### 检查 3：★ 路径空间 —— 判定单位是「可判点」，不是「路径」

**这是本轮新加的检查，也是 B4 唯一全新的东西。**

#### 3.1 每个阶段要标「有没有区分性」

**一次真跑（克里米亚）暴露的**：P01「逐步吞并」与 P02「仅威慑不吞并」的**阶段①②几乎是同一个东西** ——
危机一开始任何路径都从「俄军调动」开始，**那不是区分点，是共同前提**。

**按「阶段确认数」打分，P02 会拿到 2/3，而 P02 整体是错的。**

⇒ 每个阶段必须有 `discriminating` 布尔，**判定只数 `discriminating: true` 的阶段**。

```jsonc
"stages": [
  {"stage": "戒备", "discriminating": false, "observable": {...}, "window": {...}},
  {"stage": "撤回", "discriminating": true,  "observable": {...}, "window": {...}}
]
```

#### 3.2 两个读数都报

```
可判点级命中 = 确认数 / 区分性阶段总数      ← 更诚实（不奖励把路径写宽）
路径级命中   = 有任一区分性阶段被确认的路径数 / 路径总数
```

**一次真跑的实测**：路径级 1/3 = **33%**，可判点级 1/5 = **20%** —— **同一份记录差 13 个百分点。**
**报哪个不该由人挑**，两个都报。

#### 3.3 每条路径必填 `rules_out`

**一次真跑里三条路径有两条全军覆没 —— 而它们不是浪费，是【排除】的来源。**
没有它们，就没有「俄方撤回」和「西方军事介入」这两条被排除的路径。

⇒ **信息量在排除上。** 所以每条推演路径必须写明**它排除了什么**，
否则「三条里对了一条」会被读成成功。

#### 3.4 三种结果 ＋ 一个可核的「穷尽」判据

| 结果 | 含义 | 去哪 |
|---|---|---|
| **至少一个区分性阶段被确认** | 路径空间里有对的 | 记**命中**（并注明哪个阶段） |
| **区分性阶段全部落空，且窗口到期** | **路径空间错位** | ⇒ **预测坟场** |
| **窗口未到** | 尚不可判 | 留待判定队列 |

**`exhaustive_claimed: true` 是装饰性标记** —— 没有任何东西能核它。
**改成可核形式**：**事后把「实际发生的路径」与「写下的路径」对照** ——
**若实际发生的路径不在任何一条写下路径的确认范围内，那就是路径空间漏了**，记进 `space_gaps`。

**★ 这条判据在克里米亚那次真的亮了**：回看 `actualOutcome` 里「西方实施制裁但力度有限」——
那是当时一条非常可能的路径，**而它没被写进三条里。**

**★ 诚实说清：检查 3 现在【做不到全自动】。**
判据大多是自然语言，没有数据源能直接判。**做法不是假装判了，而是**：

* `threshold` + `source` 齐全的 ⇒ **自动判**
* 缺任一 ⇒ **标记「待人工判定」并进队列**，队列里带**该看什么**（`observable` 原文）
* **窗口到期时，队列会提醒**

## 四、`construct-run-v1` 的完整字段（B4 的交付物）

**这是 S5 要渲染、S6 要累积的那个格式。** 现在只有排除断言那一段（`construct-exclusion-v1`），B4 把它扩成完整的一次判断：

```jsonc
{
  "schema": "construct-run-v1",
  "run_id": "crimea-20261002T1543",
  "committed_at": "2026-10-02T15:43:00+08:00",

  // ── S1 事件登记（F1–F3）──
  "event": {
    "text": "原文，不许转述",                    // F1
    "source": {"outlet": "", "url": "", "published": ""},   // F1
    "event_date": "2014-02-22",
    "time_lock": "2014-02-22",                 // F3：只看这个时点之前已知的
    "actors": ["RU", "UA"],                    // 未建档的要显式标「无档案」
    "unarchived_actors": []
  },

  // ── S2+S3 主体诊断 ──
  "diagnoses": [{
    "actor": "RU",
    "archive_ref": "ConStruct_Archive/Tier1/Russia.md",
    "fields": { "continuity.type": "order", "config.lockMode": "swing", "...": "..." },
    "provenance": { "continuity.type": "Tier1/Russia.md:240", "...": "..." },  // S2b 的 N1
    "unknown_fields": []                        // S2b 的 N2：判不出的标未知，不许默认值
  }],

  // ── S4 路径推演（B4 新做）──
  "paths": [{
    "id": "crimea-20261002T1543-P01",
    "label": "克里米亚被俄罗斯逐步吞并",
    "direction": "affirm",                      // affirm=推演为会发生
    // ★ 一条路径有【阶段】—— 它不是二值的（真跑修正 G1）
    "stages": [
      {"stage": "控制", "discriminating": false,   // ← 各国路径共通的起点，不算这条的成绩
       "observable": {"object": "克里米亚关键设施", "indicator": "出现无标识武装控制",
                      "threshold": null, "source": null},
       "window": {"from": "2014-02-22", "to": "2014-04-22"}},
      {"stage": "并入", "discriminating": true,    // ← 只有它有区分性
       "observable": {"object": "克里米亚", "indicator": "俄方签署条约并入俄联邦",
                      "threshold": null, "source": null},
       "window": {"from": "2014-02-22", "to": "2014-12-22"}}
    ],
    // ★ 必填：这条路径【排除了什么】（真跑修正 G3 —— 信息量在排除上）
    "rules_out": ["克里米亚维持乌克兰控制", "俄方撤回基地", "西方军事介入"],
    "verdict": {"kind": "confirmed",            // confirmed / partial / missed / open
                "discriminating_hits": 1, "discriminating_total": 1},
    "probability": "high",
    "why": "自由文本，保留但【不参与核】"
  }],

  // ── S4 排除断言（已有，形状统一）──
  "exclusions": [{
    "id": "crimea-20261002T1543-X01",
    "excluded": "北约出兵协助乌克兰",
    "direction": "exclude",
    "observable": {
      "object": "北约成员国军队",
      "indicator": "出现在乌克兰境内并与俄军直接交战",
      "threshold": null,
      "source": null
    },
    "window": {"from": "2014-02-22", "to": "2017-02-22"},
    "why": "自由文本"
  }],

  // ── 判定（由【引擎】算，记录里存的是快照）──
  "checks": {
    "structure": { "missing_criterion": [], "missing_window": [] },   // 检查 2 的一部分
    "criterion_relevance": { "off_topic": [] },                      // 检查 2
    "exclusion_falsified": [],                                       // 检查 1（可能为空 = 尚未被证伪）
    "path_space": {                                                  // 检查 3（真跑修正后）
      "confirmed": [], "missed": [], "open": [],
      // ★ 两个读数都报，不让人挑（真跑修正 G2）
      "readout": { "path_level": "1/3", "point_level": "1/5",
                   "discriminating_total": 5, "confirmed_points": 1 },
      "mismatch": null,
      // ★ 可核的「穷尽」判据：实际发生的路径不在任何确认范围内 ⇒ 这里会有东西（真跑修正 G4）
      "space_gaps": ["西方实施制裁但不改变结果（回看 actualOutcome 发现，未写成路径）"]
    }
  },
  "pending_manual": [                            // ★ 不能自动判的，排队，不假装判了
    {"judgment_id": "...", "observable": "...", "window_to": "...", "why_manual": "无数据源"}
  ],
  "readout": { "paths": 1, "exclusions": 1, "problem_ratio": 0.0 }
}
```

**三条字段规矩**：

1. **`why` 与 `observable` 分开** —— `why` 是给人读的理由，`observable` 是给机器核的判据。
   **现在的病就是把两者混在一栏**（三条真实记录里两条把理由填进了判据栏）。
2. **`direction` 显式** —— `affirm`（推演为会发生）／`exclude`（断言不会发生）。
   **同一个形状承载两个方向**，检查逻辑才能复用。
3. **`checks` 是快照不是真相** —— 真相由引擎每次重算；记录里存的是「当时怎么判的」，便于对账。

## 五、判定逻辑放哪（本轮反复强调的规矩）

> **判定逻辑全在引擎里，前端只显示。**
> **免得同一件事有两套口径** —— 本项目已经吃过「版本号三处不一致」「两份同 title 不同内容」的亏。

**⇒ B4 要在 `construct-engine/` 加 `judgment_ledger.py`**，职责：

| 职责 | 说明 |
|---|---|
| **结构校验** | `observable.object` / `indicator` 必填、`window` 必填 ⇒ **缺一阻止提交** |
| **判据对不对题** | 结构化版（`object` 是否出现在事件主体/路径内容里）＋ 词面重叠（保留为粗筛） |
| **检查 1** | 调 `exclusion_ledger` 的核对函数（`ucdpwar:` / `ucdp:` / `cow:` / `fact:`） |
| **检查 3** | 路径空间判定 ＋ 生成 `pending_manual` 队列 |
| **账与漂移** | 沿用 `exclusion_ledger` 的指纹与 `--gate` 那套 |

**并把前端那份 `criterionOverlap` 删掉** —— 它现在是引擎侧的第二实现。**前端只调引擎算好的结果。**

## 七、B4 的验收标准（可核，不是形容）

1. **缺 `observable.object` / `observable.indicator` / `window` 任一 ⇒ 阻止提交**（不是警告）
2. **三条检查全部建了，且每条都有一个【反向测试】能让它亮**
   （本轮教训：一个永远绿的检查等于没有检查）
3. **记录格式定稿** —— S5 能按它渲染、S6 能按它累积
4. **`pending_manual` 队列存在**，且**队列里的条目不许被静默当成「尚未被证伪」**
5. **前端不再有判定逻辑**（`criterionOverlap` 之类全部移走）
6. **三条真实记录能迁移进新格式**（古巴／克里米亚／海湾那三条），迁移后可复跑对账

## 八、照实记：B4 里我还不确定的三件事

1. **`threshold` + `source` 的覆盖率能有多高？**
   三条真实记录的判据全是自然语言，**可能大多数都进不了自动判定**。
   ⇒ **这会导致 `pending_manual` 队列很长**。那是不是说明「判据该写成可计算的」这个要求过严？
   **要等真的用它写几条判断才知道。**

2. **检查 3 的「窗口到期」由谁来触发？**
   工具是 `file://` 打开的，**没有后台**。到期提醒只能在**下次打开时**做。
   ⇒ 若要真提醒，需要 S6 有个常驻的地方（部署到 web.app，或用本地脚本扫）。**这条待定。**

3. **`direction: affirm` 的路径，确认了是「命中」还是「证实」？**
   本轮的规矩是**单向可证伪**：排除断言被证伪才有信息，没被证伪只说明「尚未」。
   **推演路径反过来**：被确认是「命中」——但那也只是**未被证伪**的一种。
   ⇒ **措辞要小心，不许把「命中一条」说成「模型对了」。**
