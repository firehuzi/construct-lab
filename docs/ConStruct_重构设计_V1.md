## 一、为什么要重构（诊断，带证据）

不是「有几个 bug」，是**没有设计**的必然结果。以下缺陷全部来自 2026-10 这一轮的实测，不是印象：

### 病型 0（最根本）：核心资产根本不在版本控制里

实测（`git ls-files` 逐目录比对）：

| 目录 | 文件数 | 被 git 跟踪 |
|---|---|---|
| `docs`（全部立项书／路线图／设计文档） | 73 | **0** |
| `actors` | 84 | **0** |
| `content` | 143 | **0** |
| `ConStruct_Archive`（47 档案） | 79 | **0** |
| `CWKB_Vault` | 43 | **0** |
| `construct-stack`（数据栈） | 3166 | **0** |
| **合计** | **3588** | **0** |

**根目录有一个【空的 `.git` 目录】** —— 所以根不是仓库，`git` 直接报
`fatal: not a git repository`。只有 `construct-engine`（508 文件，remote = `firehuzi/construct-lab`）
和 `construct-lab-site` 有仓。

**⇒ 这一条解释了下面好几条**：两份同 title 的副本、`框架v3.0.html` 零命中却在清单里、
`CWKB_v3.0_source.txt` 与 `v3.0.txt` 字节相同 —— **没有版本控制，所以没人知道哪个是哪个，
也无法追溯谁在什么时候改了什么。** 「47 份档案」这个最强资产，目前**只存在于一块硬盘上**。

### 病型 1：声明与产物从不互相对照

| 实例 | 事实 |
|---|---|
| 八维值域文档称「代码真相」 | 而那份代码**全工作区零命中** |
| `world_map.html` 标题称「GDELT 实时」 | 全文 `GDELT` 只出现 **1 次**（就在标题里） |
| 06-26「完成内容」清单 | **每一行 ✅**，而 7 天前 v2.0 定的**三道可证伪判据一条都没跑过**（机器核出：`docs/` 里 0 处结果记录） |
| 案例卡 vs Case JSON Schema | 10 个字段里 **缺 9 个**，而 schema 是 4 小时前刚声明的 |
| 工具导出 | 两处**静默 return**：点了没反应，不产文件 |

### 病型 2：设计的东西没建，或建了没接

| 实例 | 事实 |
|---|---|
| 立项设计的 **SQLite 唯一真相源** | **从未建**（`db/` 空，`schema.sql` 零命中） |
| `rules/` 每个主体一份规则 | 实测 **5 个文件 / 47 主体** |
| `Event_Chains` / `Strategy_Timeline` / `Indexes` | **三个目录空**（而 `Indexes` 是设计里连接知识层与引擎的枢纽） |
| `预测坟场`（记录失败预测） | **只有 1 条** —— 而它的意义是持续记录失败 |
| **L5 维持机制层** | 让用户评四项，**只有 `legitimacy` 被读**；忠诚／仪式／叙事填了没人用 |
| **三条反馈回路** | 标题写「线性栈 → 闭环」，实测是**纯展示文字**，不进 `state`、不进诊断 |
| **底盘六层**（地理→经济→历史→文化→族群→创伤锚点） | 是**另一条线**（地缘推演台）的结构；**两条线从未合并**，工具里「地理 0 处、族群 0 处」 |

### 病型 3：词汇与版本不统一

* 47 份档案与工具**不共享一套词汇**，且长期**没有导入路径**（审计 F20 才补上）
* **三套版本号并行**；`v2.1.html` 内部标 v2.2
* **两份 `<title>` 完全相同的文件，内容差 11 KB** —— 本轮我差点拿错当基座
* `CWKB_v3.0_source.txt` 与 `CWKB v3.0.txt` **字节完全相同**（同一份两个名字）

### 病型 4：口径不对题（做检查的人自己也会犯）

本轮**我的审计器自己犯了三次同型错误**，全部记在代码注释里：

1. 只看 `state.` 字面量 → 层里用的是字符串路径（`updateState('id','path')`）⇒ 逐层全显示 0
2. `Object.entries(state.fears)` 是**动态读** ⇒ 差点把「诊断的核心输入」（L8 四个恐惧）误报成「只写不读」
3. 切分正则要求 `layer-icon` 后紧跟 `>`，而 L11 的 span 带 `style` ⇒ **L11 整块被并进 L10**，我据此得出「工具里没有 L11」的**错结论**

**⇒ 结论：摸石头过河是有效的探索方式，但探索完必须回头定图纸。现在回头。**

## 二、目标规格

```
输入：一件地缘政治事件（当前或过去）
      { 时间, 描述, 涉及主体（可留空由系统识别）, 出处 }

输出：一份分析报告
      { 主体诊断, 传导分析, 排除断言（含证伪条件与窗口）, 追溯表 }
```

**这句话的分量在「端到端」**：它要求**整条链都通**，而不是像现在这样「每一环各有各的完成度」。

## 三、阶段划分

| 阶段 | 做什么 | 判据 |
|---|---|---|
| **B（先）** | **分析者判断 ＋ 系统强制结构**：系统负责识别主体、加载档案、预填、逼你写证伪条件与窗口、累积成账；判断由分析者下 | 见 §七 验收标准 |
| **A（后）** | **自动推导**：把 B 中被证明有效的步骤编码 | 见 §八 闸门 |

**为什么 B 必须先跑通**：B 是 A 的规格书。**每一次手工判断里，有价值的步骤成为自动化候选，没价值的直接砍。** 先自动化一个没验证过的流程，只会把分歧藏起来。

**并且有一条证据支持这个次序**：本轮所有**全自动**的尝试都失败了（八维的轴到数据天花板、GDELT 读出口无效应、选择偏倚把 ρ 从 +0.507 打到 +0.263）；而**手工的结构化判断是对的**（克里米亚那次：路径预测命中、排除断言成立、判据修正后合格）。

## 四、一条管道（B 阶段的全部工作）

**核心规矩：每一段都必须产出【结构化产物】，不能只有文字。**

| 段 | 输入 | 输出 | **怎么核它真的通了** |
|---|---|---|---|
| **S1 事件登记** | 事件描述 + 日期 + 出处 | 事件记录 ＋ 涉及主体列表 | 主体必须在档案里存在；**不在就明确标「无档案」，不许静默通过** |
| **S2 主体加载** | 主体 id | 诊断预填（L2–L8） | **每个预填字段都带出处**（哪个档案文件的哪一行） |
| **S3 结构诊断** | 预填 ＋ 分析者修订 | 11 层状态 ＋ 诊断结论 ＋ SUL | ① **L5 四项全进诊断**；② **反馈回路要么真算、要么从标题撤掉「闭环」** |
| **S4 判断登记** | 路径推演 ＋ 排除断言 | `construct-run-v1` 记录 | **证伪条件必填、窗口必填**；判据与被排除路径的**对不对题检查**；缺一即**阻止进 S5** |
| **S5 报告生成** | S3 ＋ S4 | 报告（Markdown / 公众号 HTML） | **报告里每个结论都能追到 S3/S4 的某个字段** |
| **S6 归档累积** | 报告 ＋ 记录 | 账（排除断言）＋ 历史（推演记录）＋ 坟场 | 可复跑对账；**内容指纹防过期**（结论不许悄悄失效） |

**管道里已经能用的零件**（本轮实测可跑）：

* S4／S6：`exclusion_ledger.py`（31 条自证）／`claims_ledger.py`（28）／`build_tool.py`（29）／`audit_layers.py`（10）
* S2：`loadArchive` ＋ 47 档案（**L2–L8 字段齐备**，抽样 3 份全中）
* S5：`genGzhHTML` / `genSubstackMD` / `exportReport` / `publish_article.py`

**管道里缺的**：

* **S1**（没有「输入一件事件」的入口 —— 现在是让你从零填 11 层表单，**这与原始意图已经不是一个东西**）
* **S2 的出处字段**（档案里有内容，但没有「哪一行」的可追标记）
* **S3 的 L5 接线 与 反馈回路**

## 七、验收标准（可核，不是形容）

B 阶段算跑通，当且仅当以下**全部**成立：

1. **端到端**：只给一件事件，**不改代码**，产出报告
2. **可追**：报告里每个结论都能追到「某个字段 + 某个出处」
3. **可证伪**：所有排除断言都有**证伪条件 ＋ 窗口**；缺一即**阻止出报告**（不是警告，是阻止）
4. **可复现**：同一事件、同一输入，两次跑**字段级可比**（不要求字面相同）
5. **可累积**：每次跑完账 **+1 条**，且账能复跑对账（`--ingest` ＋ 漂移闸门）
6. **有时限**：单次「事件 → 报告」≤ N 分钟。**N 由第一次实测定，不由现在猜。**
7. **可交付他人**：把工具与输入给另一个人，**他能跑出同形状的报告** —— 否则这不是系统，是个人风格

## 八、B → A 的闸门

**B 跑通 ≥ 10 次之后**，才允许启动 A。届时按以下规则定自动化候选：

| 指标 | 含义 | 用途 |
|---|---|---|
| **人工耗时占比** | 每一步花的时间 | 占比高的优先 |
| **判断一致率** | **两个人独立走同一事件**，同一字段给同一答案的比例 | 一致率高才可自动化 |

**硬规矩：一致率低的步骤【不许】自动化。** 那是把分歧藏进代码里 —— 而分歧恰恰是最需要暴露的东西。

## 九、非目标（明确不做）

* **不做自动预测** —— 框架的定位是「标记逻辑上不可能的路径」，不是预测
* **不做跨域**（金融／社会／影视）—— 在地缘跑通之前。第 4137 行那句「地缘分析、电影分析、刀具数据库都可以成为不同训练域」是**终局**，不是下一步
* **不接新数据源** —— 直到现有数据（UCDP 已落地／COW／GDELT 采集器）被真正用上
* **不加新层** —— 工具已经有 13 个层块，先把 L5 和反馈回路修好
