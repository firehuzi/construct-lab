# ConStruct Lab · 分析工具（引擎/工具层新版）

`tool/index.html` 是**构建产物**。不要直接改它 —— 改了会在下次构建时被覆盖。
改基座或引擎，然后重新构建：

```bash
python build_tool.py            # 构建 tool/index.html
python build_tool.py --selftest # 14 条自证
```

---

## 为什么是「单文件 + 构建器」这个架构

工具要能**双击直接打开**（`file://`，无需服务器）。而 `file://` 下浏览器
**不允许页面加载同目录的其它 `.js`/`.json`**（CORS）。所以：

* 数据不能 `fetch` ⇒ 必须**内联**进 HTML
* 模块不能拆成多个 `.js` ⇒ 必须拼进同一个 `<script>`

这决定了分工：**引擎（Python）算 → 构建器内联 → 单文件交付**。

**★ 判定逻辑全在引擎里，前端只负责显示。** 免得同一件事有两套口径
（这个项目已经吃过「版本号三处不一致」的亏）。

## 板块

| 板块 | 来源 | 说明 |
|---|---|---|
| ① 🧭 历史回溯 | `backtest-tool/index.html` 里 `@@MODULE:backtest@@` 之间的块 | 时间锁推演：只看当时已知的信息做判断，提交后（锁定）才揭示历史 |
| ② 📒 排除断言账 | `exclusion_ledger.ingested_rows()`（每次构建时由引擎算） | 「什么不可能发生」的断言及其全部问题 |

**上市顺序**：`backtest-tool/index.html` 是**基座**，带两个板块锚点
`<!-- @@MODULE:backtest:START@@ -->` / `@@MODULE:backtest:END@@ -->`。
构建器靠这两个锚点把基座包成板块①，并插入板块②③。**锚点丢了构建会直接报错**
（不静默产出一个缺板块的产物）。

## 板块① 的规矩（这一条是这个工具的立身之本）

```
时间锁（只看当时已知的信息，不看结果）
   ↓
写下判断：路径推演 ＋ 排除断言（证伪条件必填、窗口必填）
   ↓
✔ 提交本次推演 → 写入历史、锁定
   ↓
揭示历史 🔓（没提交就揭示不了）
```

**「没提交就揭示不了」不是防呆，是方法论**：否则你的判断会在看到历史结果
之后改变，那就不是事前判断了。事后诸葛亮是廉价的。

### 两条排除断言的硬规矩

1. **证伪条件必填**，而且它写的是**「它发生了」= 出现什么**，
   不是「我认为会怎么走」（那是路径预测），也不是「为什么会这样」（那是理由）。
   缺它 ⇒ 断言不可证伪 ⇒ **不携带信息**。
2. **窗口必填**。没窗口 ⇒ 只能说「尚未发生」。而**窗口决定真值**：
   真实案例 —— 「盟军入侵伊拉克」在 1991 年成立（联军停在边境），
   在 2003 年被证伪（美英入侵）。**同一个断言，窗口不同，真假相反。**

工具会就地检查这两条；`exclusion_ledger.py` 侧也会再判一遍并累积成账。
