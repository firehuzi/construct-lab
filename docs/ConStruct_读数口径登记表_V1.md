# ConStruct Lab · 读数口径登记表 V1

> 建立日期：2026-10-02 ｜ 状态：待评审
>
> **这份表解决一个具体的病**：本项目多次出现「**读数是对的，但没人知道它在量什么**」——
> 于是同一个数字被当成两种意思用，而**两种解释都成立时，人不自觉地只挑一条写**。
>
> **写法借鉴自 TaoPaw 的 `缺口清单.md`**（另一条线，同源纪律）。它那里有一节
> **「三条读数口径（⛔ 引用前先看这里）」**，并明文禁止一种写法：
>
> > ⚠️ 这是**尺子的缺口**，⛔ 不是「机制没生效」的证据 ——
> > **两条解释（剂量太小 / 尺子看不见）现在都成立，⛔ 不许只挑一条写。**
>
> **而我们的第二个独立操作者报的原话是**：
> 「② 人判＋依据可核这一格恒等于 0，**而没人知道这个 0 是接口错，还是案例真的没有依据**。」
> —— **一字不差是同一件事。我们从没这么规定过，所以它发生了。**

---

## 怎么写这一行

每条读数三样，缺一不算写完：

| 字段 | 问的是 |
|---|---|
| **它实际量的是什么** | 代码里那个值从哪来、代表什么 |
| **⛔ 不许怎么说** | 最容易出的错读法 |
| **什么情况下它量不动 / 会误导** | 量不动时它会显示成什么（这是最容易被当结论的） |

---

## A. 判定侧

### A1 · `③ 待人工占比`

| | |
|---|---|
| **实际量的是** | **工具支持的函数**，不只是案例的函数。**它同时量三样**：① 案例有没有数据源；② **工具认不认识这个主体**；③ evidence 有没有过闸 |
| **⛔ 不许怎么说** | 不许说成「**这个案例数据不足**」——那只是三种成因里的一种 |
| **量不动 / 误导** | **实测过一次：恒等于 0 的那种坏法**。修 `evidence.slug` 之前，「② 依据」恒等于 0，**而这个 0 与「案例真的没依据」在读数上完全一样**。另一个实例：印巴案例的 93% 里有相当一部分成因是**别名表里没有 CN/IN** ⇒ 不是「没数据」，是「工具不支持」 |

**★ 引用前的规矩**：**比较两个案例的占比时，必须先确认工具对两边的主体支持程度一样、且依据核验路径是通的。**

### A2 · `② 人判＋依据可核`

| | |
|---|---|
| **实际量的是** | **过了三道机器闸的 evidence 条数**（① slug 在索引里 ② `verified_open` ③ `witness_type=contemporary`） |
| **⛔ 不许怎么说** | 不许说成「有依据的判断」——**它量的是【过了闸的】**，没过闸的一条都不计 |
| **量不动 / 误导** | **2026-10-02 实测：修之前恒等于 0**（`load_sources()` 按文件名建索引，而 `evidence.slug` 按 slug 字段写 ⇒ 8/8 全不过闸，**而报错说「不在索引里」而索引里就有**）。⇒ **这个字段曾经是一个恒 0 的坏读数，而它长得和「真的没有依据」一模一样** |

### A3 · `① 机器自动判`

| | |
|---|---|
| **实际量的是** | **有 `source` 且工具认得那种写法的**判断数 |
| **⛔ 不许怎么说** | 不许说成「可自动化的比例」——它同时受**别名表覆盖率**影响 |
| **量不动 / 误导** | 别名表外的码 ⇒ 静默判到**别的双边对**（实测：`CN,IN` 命中 `India\|\|NSCN-IM`，死亡数报 7 而真值 25）。**错读数与对读数长得一样** |

### A4 · `区分点提示`

| | |
|---|---|
| **实际量的是** | **字符二元组重叠度**（不是语义） |
| **⛔ 不许怎么说** | 不许说成「这些阶段区分不开」——**它分不出「相同」与「相反」**，而区分点最常是一对相反阶段 |
| **量不动 / 误导** | **两个方向都错**：海湾那次报了 74% 重叠的一对（**它们是相反的**）、漏了「停火是共通终点」那条；印巴那次 4 对**全假阳性**、印巴第二次 2 对**全判对** ⇒ **它的准确率取决于措辞风格**。**⇒ 它的产出不该当成发现用。** |

### A5 · `G6 链式确认 / 前缀未判 / 链断在开头`

| | |
|---|---|
| **实际量的是** | **`discriminating` 阶段的前缀连续命中数** |
| **⛔ 不许怎么说** | 不许说成「**因果链已验证**」——**它抓的是「前缀没中」，抓不了「前缀中了但原因不同」** |
| **量不动 / 误导** | ① **`chain_hits=0` 那条路上，「没判」与「判了没中」仍同名**（`undecided` 只覆盖了链悬置）；② 实测出现过 `✖️ 链断在开头（前缀连续命中 1/1）` **这种自相矛盾的行**；③ **它把「合取」读成「因果链」** ⇒ 一位操作者被迫把路径从 2 阶段压成 1 阶段才拿到正确读数 —— **工具反过来塑造了路径空间** |

### A6 · `断言的判定词（⛔ 被证伪 ／ ⏸️ 尚未被证伪 ／ ✅ 确认 ／ ✖️ 落空）`

| | |
|---|---|
| **实际量的是** | `observed` ＋ **断言方向**（排除 / 推演）的映射结果 |
| **⛔ 不许怎么说** | **排除断言的判定词里永远不出现「确认」** —— 单向可证伪，没发生只能叫「尚未被证伪」 |
| **量不动 / 误导** | **实测踩过两次**：① 我给排除断言写了 `present` 的 source，而「无事件」被判成**证伪**（反了）；② 一位操作者的 indicator 写「未达到 100 死」而 source 测「达到 100」⇒ 工具印 **✖️ 落空**，而断言方向上是**确认**。**⇒ 符号是反的，而 ✖️ 长得和「确实落空」一样。** 代码里有 `looks_opposite()` 这个现成钩子，**没接到这里** |

### A7 · `space_gaps`（路径空间漏了什么）

| | |
|---|---|
| **实际量的是** | **回看历史**算出的遗漏 |
| **⛔ 不许怎么说** | ⛔ **不许说成「防止了遗漏」** —— 它证明检查**能亮**，**没能证明它能提前防止** |
| **量不动 / 误导** | **它与时间锁定直接冲突**：填它就必须知道实际发生了什么。⇒ 现在一律填 `null` |

## B. 数据侧

### B1 · `arm: high / quiet`

| | |
|---|---|
| **实际量的是** | **选择规则的分档线**（high = 死亡 ≥1000；quiet = 死亡 ≤25） |
| **⛔ 不许怎么说** | ⛔ **不许把 `quiet` 读成「安静」** |
| **量不动 / 误导** | **实测：CN-IN 2020 被标 `quiet`，而那年是加勒万河谷冲突（25 起死亡）** —— **一次致命冲突被叫成「安静」。** 且 `QUIET_DEATHS=25` 的理由原写「UCDP 收录下限」，**与数据矛盾**（数据里有 8 条 0 死亡单元）。⇒ 已加 `dyad_years_in_data` 与 `label_caveat` |

**★ `label_caveat` = 「该双边对在数据里只有 N 年记录 ⇒ 这一条不是某场冲突的安静年，它是这个对唯一出现的那一年」。**

### B2 · `meets_war_threshold` / `deaths`

| | |
|---|---|
| **实际量的是** | 该双边对的**年度战斗死亡合计**，对照 UCDP 自己的战争定义（≥1000） |
| **⛔ 不许怎么说** | 不许把「无记录」说成「没发生」 |
| **量不动 / 误导** | **「该对记录过事件而某年无记录」才有信息**（前提必须写明）。**找不到双边对 ⇒ 判 `insufficient_data`，不许判「无事件」**（写死在代码里）。另：**覆盖期外的年份**（COW 止于 2014）⇒ **判「数据不够」，不许判「尚未被证伪」** |

### B3 · `geo_present` / `geo_breadth`

| | |
|---|---|
| **实际量的是** | 某行政区的事件数 / 事件铺开的行政区个数 |
| **⛔ 不许怎么说** | ⛔ **不许把 `observed=False` 读成「那里没打」** |
| **量不动 / 误导** | ① **地名是被观察方命名的** —— 写 `Ladakh` 得到「无」，**不是没打，是那个地名在数据里不存在**；印巴 2023 那一年，**只有印方写法 `Jammu and Kashmir state` 在数据里** ⇒ **哪一侧地名在数据里，本身携带一方的立场**。② **`geo_*` 不吃别名**（`geo_present(India, Pakistan, …)` → `None`；写 `IN, PK` 才对）。③ `geo_breadth` 在**平静双边对上退化成常量**（印巴一直 1–5 个州，阈值 1 永远真、≥3 永远假） |

### B4 · `verified_open` / `witness_type`

| | |
|---|---|
| **实际量的是** | 依据**取到了吗** / 它是**当时的还是事后的** |
| **⛔ 不许怎么说** | ⛔ **不许说「存档成功 = 内容可用」** —— 付费墙、JS 壳、错误页都可能返回 200 |
| **量不动 / 误导** | ① `witness_type` 的判定**必须由内容给**（govinfo 那份 1991 年文件 URL 无日期，只从 URL 猜会判 `unknown` ⇒ **最有价值的依据被判成不可用**）；② 判据是**可读文本量**，不是「有没有 paywall 这个词」（三条带 paywall 标记而文章文本齐全）；③ `evidence` 块里的 `witness_type`/`published`/`url`/`verified_open` **一个都不被读**，工具只读索引记录里的同名字段 |

## C. 执行侧

### C1 · `--selftest` 通过数

| | |
|---|---|
| **实际量的是** | **「这段逻辑按我设想的走吗」** |
| **⛔ 不许怎么说** | ⛔ **不许说成「工具是可信的」** |
| **量不动 / 误导** | **296 条自证，三个盲测者报出的 6 个 bug【一条都没抓到】**。因为它们全是我按自己已知的坑写的。**自证测不出「不知道的人会怎么错」。** 实例：修 `evidence.slug` 之前，60 条自证**没有一条碰过 `check_evidence` / `load_sources`** |

### C2 · `同输入两次跑 ⇒ 逐位相同`

| | |
|---|---|
| **实际量的是** | —— **我们【没有】这个读数** |
| **⛔ 不许怎么说** | ⛔ 不许假设它是真的 —— **从没测过** |

## D. ⛔ 一条明文禁止（借自 TaoPaw，逐字适用）

> **当一个读数的成因有两种以上解释，而它们都成立时 —— ⛔ 不许只挑一条写。**
>
> **要写「两条解释都成立，现在分不清」，并给出能把它们分开的那次测量。**

**本项目已经违反过它三次**（都是撞出来的，不是主动发现的）：

1. **「② 依据 = 0」** —— 是接口错，还是案例没依据？**当时分不清，而报告写成了后者。**
2. **「待人工 93%」** —— 是数据不足，还是工具不支持这个主体？**两条都成立。**
3. **「区分点提示报了 4 对」** —— 是它们真的相似，还是我的口径分不出相反？**两条都成立。**

## E. 怎么用这张表

- **引用任何一条读数前，先看这里有没有它。**
- **写新读数时，三条（量什么 / 不许怎么说 / 何时量不动）缺一不算写完。**
- **发现「量不动」的新形态时，补进第三栏** —— 那一栏是本表最值钱的地方，
  因为**量不动时读数长得和结论一样**。
