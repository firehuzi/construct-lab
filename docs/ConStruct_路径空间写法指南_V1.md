# ConStruct Lab · 路径空间写法指南 V1

> 读者：**拿到一份案例骨架（`construct-case-skeleton-v1`）、要把它填成路径空间的人。**
> 日期：2026-10-02 ｜ 状态：待评审
>
> **这份指南存在的理由**：写路径空间的规矩原本散在四个文档里
> （B4 规格、克里米亚试写、海湾试写、L2L8 判据）。而 B 阶段有一条验收标准是
> **「把工具与输入给另一个人，他能跑出同形状的报告」** —— **规矩不集中，那一条永远不成立。**
>
> ★ 本指南里每一条规矩都注明**它是哪一次真实错误逼出来的**。没有实例的规矩不写。

## 〇、一句话

> **路径空间是「若干条可能路径 ＋ 若干条不可能路径」，每条都带【什么算它发生了】。
> 信息量在【边界】上，不在【命中了多少】上。**

**「A/B/C 可能」几乎不携带信息；「D/E/F 不可能」才携带信息。**
（出处：克里米亚试写。三条路径里两条全军覆没 —— 而它们不是浪费，是排除的来源。）

## 一、填之前：先做时间锁定

**规则 1：只放【事件发生时已知的信息】。**

历史事件必填。**你知道结局，这是最大的污染源。**

```
❌ 「1991 年 1 月，伊拉克将拒绝撤军」
✅ 「1991 年 1 月 15 日——安理会 678 号决议最后期限已过，伊拉克拒绝撤军」
```

**规则 2：`event.text` 必须是【原文】，不是复述。** 拿不到原文就**留空并标 `needs_human`**，**不许编**。

> **实测：两次真跑（海湾 1991、俄乌 2022）的 `event.text` 我都留空未编。**
> **两次都留空，说明「补原文」是一个真实且反复出现的研究工作量 —— 不是可以跳过的形式。**

## 二、路径空间怎么搭

### 规则 3：3–5 条路径，其中至少一条是【你没预期的那条】

**少于 3 条 ⇒ 路径空间太窄，会漏。多于 5 条 ⇒ 每条都写不细。**

### 规则 4：路径【不互斥】—— 别指望「只有一条会中」

**实测（克里米亚）**：「俄罗斯逐步吞并克里米亚」与「西方实施有限制裁」**两条都发生了**。

> **⇒ 所以「三条里对了一条」听起来像成功，其实只说明你的路径空间【宽到什么都装得下】。**

### 规则 5：每条路径必填 `rules_out` —— 它排除了什么

**海湾那次三条路径里两条全军覆没 —— 而它们不是浪费，是【排除】的来源。**
没有它们，就没有「俄方撤回」和「以色列还击」这两条被排除的路径。

### 规则 6：不要写 `exhaustive_claimed: true`

**它是一个没有任何东西能核的装饰性标记。**（实测：克里米亚那次的路径空间就漏了一条 ——「西方制裁但不改变结果」。）

**改用可核形式**：事后把「实际发生的路径」与「写下的路径」对照，**不在任何确认范围内 ⇒ 记进 `space_gaps`**。

**★ 但要知道它的局限**：`space_gaps` 是**回看历史**才算得出来的 ——
它证明检查**能亮**，**没能证明它能提前防止遗漏**。（海湾、克里米亚两个案例的 `space_gaps` 都是回看发现的。）

## 三、一条路径怎么写

```jsonc
{
  "id": "IQ-KW@1991-P03",
  "label": "伊拉克主动撤军、避免地面战",        // 一句话，要能读出来
  "direction": "affirm",
  "probability": "medium",
  "rules_out": ["战争爆发", "科威特被长期占领"],  // ★ 必填
  "stages": [
    {
      "stage": "宣布撤军",
      "discriminating": true,                    // ★ 只数 true 的
      "observable": {
        "object": "伊拉克政府",                    // 谁/什么被观察
        "indicator": "在最后期限前宣布从科威特撤军",   // 看到什么算发生
        "threshold": null,                        // 有量化门槛就写
        "source": null                            // 有数据源就写（见 §五）
      },
      "window": {"from": "1991-01-15", "to": "1991-01-16"}
    }
  ]
}
```

### 规则 7：阶段是【因果有序】的，不只是时间有序

**这一条是 G6 逼出来的。**

**海湾 P03 的假设是「伊拉克撤军 ⇒ 联军收手」。逐阶段独立判的结果是：**
```
① 宣布撤军 → 落空
② 联军收手 → ✅ 确认        ← 确实发生了
```

**⇒ 看起来「部分成立」。而实际上 P03 整体是错的 —— 联军收手的原因是【伊拉克战败】。**

**判定规则**：**前缀连续命中才算【链式确认】。前缀断掉之后仍被确认的阶段，是【孤立确认】。**

> **孤立确认 = 某个事件发生了，但【不是这条路径说的原因造成的】。**

**⇒ 所以写阶段时，顺序必须反映因果链。若两个阶段之间没有因果关系，它们不该在同一条路径里。**

### 规则 8：`discriminating` 只标【不同路径在这里取值不同】的阶段

**这是 G5 逼出来的。**

**克里米亚那次**：P01「逐步吞并」与 P02「仅威慑不吞并」的**阶段①②几乎是同一个东西** ——
危机一开始任何路径都从「俄军调动」开始。**按阶段确认数打分，P02 拿到 2/3 —— 而 P02 整体是错的。**

**⇒ 共通的前提（前置）与共通的终点（停火）都不是区分点，一律标 `false`。**

**★★ 而这一条【机器验不了】—— 照实说清楚：**
本项目的 `check_discriminating()` 只是一个**提示**，它用字符重叠度找「词面相似的对」，而它**两个方向都会错**：

| 方向 | 实测 |
|---|---|
| **报了不该报的** | 海湾：`停在边境，不向巴格达推进` 对 `越过边境向巴格达推进` —— **它们是【相反】的**，却因为用词相同被判成 74% 重叠 |
| **漏了该报的** | 海湾：`联军收手`（共通终点）**根本没被报** —— 它的词面短而独特 |
| **假阳性 100%** | 俄乌：报了 4 对，**而它们全都是真正的相反路径**（P01 全面入侵 vs P02 有限入侵，互为镜像） |

**⇒ 结论：字符重叠度在这件事上【基本没用】。它分不出「相同」与「相反」，
也判不了「是不是所有路径共通的终点」—— 而后者恰恰是它存在的理由。**
**⇒ 标 `discriminating` 只能靠人。写完之后自问一句：「别的路径在这个阶段会不一样吗？」**

### 规则 9：区分点写在【行为】上，不是【遭遇】上

**海湾那次的措辞教训。** P04「以色列被拖入联军破裂」的区分点，初稿写的是：

```
❌ 「以色列被导弹攻击」   ← 飞毛腿攻击【确实发生了】⇒ 这么标会给 P04 一个假确认
✅ 「以色列还击」         ← 这才是区分点
```

### 规则 10：`why`（理由）与 `observable`（判据）**分开**

**实测：三条真实记录里，两条把【理由】填进了判据栏。**

```
✗ criterion =「联合国决议和阿拉伯盟友共同约束」   ← 这是理由
✓ observable.indicator =「越过伊拉克边境，进入伊拉克本土」  ← 这是判据
```

**理由写进 `why`，它保留但不参与核。**

## 四、可核的判断长什么样

### 规则 11：`observable` 能不能机器判，取决于 `threshold` + `source`

| | |
|---|---|
| **两者都有（或 source 自带阈值）** | **机器自动判** |
| **缺任一** | **进 `pending_manual` 队列** —— **不假装判了** |
| **有 `evidence`（存档的来源）** | **人判＋依据可核**（见 §六） |

**★ 进队列不是失败，是正常。** 而 **`pending_manual` 占比本身是一个读数**：

| 案例 | 待人工占比 |
|---|---|
| 海湾 1991 | 27% |
| 俄乌 2022 | 56% |

**⇒ 而这两个数的差不在年代，在【有没有官方档案】**：
海湾有完整的《美国总统公开文件》（govinfo，30 年后仍可取）；
俄乌没有一个机器可读的官方档案记录政治决定。

> **★ 「数据新旧」不是判据，「有没有官方档案」才是。**

## 五、`source` 怎么写（判据类型清单）

**格式**：`<前缀>:<类型>(参数)`，前缀（如 `UCDP:`）会被归一化掉。

| 类型 | 写法 | 判什么 |
|---|---|---|
| **双边有事件** | `dyad_present(RU, UA, 2022-2022)` | 该两边在窗口内【有】事件记录 |
| **双边无事件** | `dyad_absent(IQ, KW, 1992-1995)` | 该两边在窗口内【无】事件记录 |
| **死亡数** | `deaths(IQ, KW, 1991, 1000)` | 年度死亡 ≥ 阈值 |
| **某地有战斗** | `geo_present(RU, UA, Kyiv, 2022, 1)` | 某行政区的事件数 ≥ 阈值 |
| **战线铺开** | `geo_breadth(RU, UA, 2022, 10)` | 事件铺开到 ≥N 个行政区 |
| **取反** | `not(geo_breadth(RU, UA, 2022, 5))` | 通用取反 |

### 规则 12：`not()` 是必需的，不是语法糖

**俄乌 P02「有限入侵」的 observable 是「战线【没有】铺开」，而 `geo_breadth` 测的是「铺开了多少个州」—— 两者语义相反。**

> **⇒ 判据的形状与断言的形状不总是一致。** 与其为每种判据写反向版本（组合爆炸），不如加通用取反。

### 规则 13：★★ 用「缺失」当证据 —— 它对历史案例特别好用

**海湾 P01③「联军停在伊拉克边境」是靠【没有记录】核的**：
UCDP 里 `Australia, UK, US || Iraq` 这个对**只在 2003 年有记录，1991 年没有** ⇒ 「联军没进伊拉克本土」。

**★ 但前提必须写明**：无记录 ≠ 绝对没发生。
**对 GED 而言，「该对记录过事件（门槛 25 死）而某年无记录」是有信息的；否则判「数据不够」。**

**这条规则写死在代码里**：找不到双边对 ⇒ 判 `insufficient_data`，**不许判「无事件」**。

### 规则 14：地理判据比「有没有事件」区分力强得多

**俄乌那次的关键发现**：顿巴斯从 2014 年就在打（只是被 UCDP 编成 `Ukraine||DPR/LPR`），
**所以「有没有事件」根本分不出「有限冲突」与「全面入侵」。**

**而地理数据分得干干净净**：

```
2014 年：铺开  1 个行政区（克里米亚 2 起）
2022 年：铺开 30 个行政区、基辅州 132 起、基辅市 42 起
```

**⇒ 能用地理判据就不用「有没有事件」。**

## 六、核不了怎么办：搜索 ＋ 存档

### 规则 15：查询必须写成【当时可问的问题】

**难的不是搜索，是写出时间锁定正确的查询词。** 你知道结局，就会不自觉地搜那个结局的措辞。

```
❌ 「以色列 1991 是否还击」        ← 已经知道答案了
✅ 「以色列 1991年1月 内阁 会议」  ← 当时的人会问的问题
```

**机器可查的规矩**：**查询不许含结果词**（还击/报复/成功/失败/拒绝/倒台/瓦解/退出/未/没有…）。
`query_gen.py` 会扫一遍并标出来。

**生成器给四个入口**：时间锚 ／ 决策过程 ／ 外部约束 ／ 同期报道。
**时间只从 `window.from` 取，不从 `to` 取** —— 问的是「当时在发生什么」，不是「最后怎么样了」。

### 规则 16：★★ 依据必须过三道机器检查，缺一道就退回待人工

| # | 检查 | 不过会怎样 |
|---|---|---|
| ① | `slug` 在 `data/sources/index.json` 里 | 来源不明 |
| ② | `verified_open == true` | **这条依据不存在** |
| ③ | `witness_type == contemporary` | **不能用于时间锁定** |

**⇒ 这是让「填了依据」不等于「过了」的机制。**

### 规则 17：存的是【原文快照】，不是链接

**链接会烂。实测两次**：`develop.baltimoresun.com`（开发域名，打不开）；
`web_fetch` 对 wikipedia／archive.org／govinfo.gov **全部误报**「非公网 IP」（那只是代理的 fake-IP）。

**每条依据要存**：`archived_snapshot`（原文）、`sha256`（证明判定时看的就是这些字节）、
`fetched_at`（不记时间不可复现）、`query_used`（否则回溯不了「我是怎么找到它的」）。

### 规则 18：`witness_type` 必须由【内容】判，不能只从 URL 猜

**govinfo 那份 1991 年的政府文件 URL 里没有日期，只从 URL 猜会判成 `unknown`，而 `unknown` 不能用于时间锁定 ⇒ 最有价值的依据被判成不可用。** 而正文里明明写着「February 26, 1991」。

**优先级**：URL 特征（维基等 ⇒ retrospective，优先）→ 正文成文日期 → 都判不出 ⇒ `unknown`（保守）。

## 七、写完自查清单

```
□ 时间锁定做了吗？只放了当时已知的信息吗？
□ event.text 是原文吗？拿不到是不是留空标了 needs_human（而不是编）？
□ 3–5 条路径？其中有没有一条是「我没预期的那条」？
□ 每条都写了 rules_out 吗？
□ 阶段是按【因果顺序】排的吗？（不是时间顺序）
□ discriminating 只标在【不同路径取值不同】的阶段吗？
   —— 共通的前提与共通的终点是不是都标了 false？
□ 区分点都写在【行为】上，不是【遭遇】上吗？
□ why（理由）和 observable（判据）分开了吗？
□ observable 有 source 吗？没有的话，它是进队列（正常）还是被假装判了？
□ 「没有发生」的判据，有没有用【缺失】当证据？前提（该对记录过事件）写了吗？
□ 能用地理判据的地方用了吗？
□ 核不了的，查询写对了吗（不含结果词、时间从 from 取）？
□ 找到的依据过三道机器检查了吗？存的是原文快照吗？
```

## 八、★ 已知的、这份指南解决不了的

**照实记，免得你以为照着做就没有缺口了：**

| # | 缺口 | 状态 |
|---|---|---|
| **G5** | 共通前置被误算成确认 | ✅ 修了（`discriminating`） |
| **G6** | 因果链缺环 | ⚠️ **部分修**（前缀规则）—— **抓不了「前缀中了但原因不同」** |
| **区分点** | 机器判不了 | ⚠️ 提示实测假阳性 100%，**只能靠人** |
| **补原文** | 人力活 | ❌ 未解 |
| **窗口起点** | 由人定，**没有任何东西约束** | ❌ 未解 —— 定在 2022-02-23 还是 2-21 或 2021 年底，路径空间会不同 |
| **`space_gaps`** | 只能回看历史才算得出 | ❌ **没能证明它能提前防止遗漏** |
| **路径空间穷尽性** | 无判据 | ❌ 同 `space_gaps` |
